TX1 — Mandatory participating-owner execution, proposed technical choice

TX1.1 Repository-fit decision
PgPayRunPort::write already owns SQLx begin, Company RLS, payroll writes and ont_action_command_receipts. Governance four_eyes_consume_conn already accepts PgConnection, but only validates request/kind/target and consumes in its caller transaction. Payroll adapter cannot depend on governance adapter: layer-boundary forbids adapter->adapter. Existing orgchange EmploymentTransferPort and app PgEmploymentTransferPort show the exact fitting solution: consumer-declared borrowing port, composition-root implementation forwards to the actual owner's transaction function.
Choose PayRunParticipants, a mandatory typed borrowed-connection participant port declared in payroll/adapter-postgres and wired by console-app. It is a concrete multi-owner transaction requirement, not a pluggable business engine or arbitrary callback list. App adds no SQL/business rules, commits nothing and never changes org_id. Participant methods return borrowing futures tied to the SAME &mut PgConnection; they cannot spawn detached work, retain the connection, open another pool transaction or treat an outbox ACK as completion. No sqlx in domain/application, new payroll application crate, unsafe pointer, gate exemption or second governance writer.
Conceptual signatures (not compiled Rust): acquire_authority_facts(conn, ServerExecutionIdentity, CommandBinding) -> FencedAuthorityFacts; acquire_bound_work_fences(conn, FencedAuthorityFacts, BoundWorkRefs) -> FencedWorkFacts; authorize_new_effect(FencedAuthorityFacts, FencedWorkFacts, AuthoritativeReceiptAbsence) -> NewEffectAuthority; check_execution_gate(conn, LockedDecisionBinding) -> GateReadiness; consume_execution_gate(conn, LockedDecisionBinding) -> GateConsumption; finalize_bound_work(conn, FencedWorkFacts, NewEffectAuthority, OwnerEffectReceipt) -> CompletionProof. A missing required participant fails enrollment at composition and fails closed at runtime. Policy-derived NotRequired is a typed server verdict bound to current policy revision, never Option<callback> or a client flag. Dedicated read-disclosure path precedes replay; it must not require permission to execute an already committed historical action. FencedAuthorityFacts and FencedWorkFacts collect trusted current facts/locks without rejecting solely for loss of new-effect permission or obsolete assignment/custody eligibility. Enforce those new-effect verdicts only after authoritative absence is established. Invalid authentication or denied current receipt disclosure still denies readback; no prior grant is revived.
Split existing lifecycle lock/validate from mutation within the payroll owner so callers cannot consume a gate then discover an unvalidated decision basis. This is a focused owner refactor with preserved low-level tests, not reimplementation of the state machine. Make raw enrolled mutation helpers inaccessible outside the guarded executor where feasible; all remaining callers inventoried and denied or routed explicitly.

TX1.2 Adapter equivalence and receipt binding
Canonical /api/v1/ontology/actions/{action_key}/{preflight|execute}, direct payroll REST, UI form handlers and Group Company children normalize to one typed owner command. Existing direct submit/decide/close/calculate helpers cannot continue as an enrolled bypass. Server-owned protocol enrollment selects the new path from the target run/definition; a request cannot opt into LEGACY. Missing new required witnesses yields428 precondition_required without mutation; semantically inapplicable old global submit/decision on PC1 runs is409 incompatible_review_protocol with a permitted new-action link. Existing non-enrolled routes retain their compatibility behavior until their own reviewed migration.
Reuse ont_action_command_receipts Company-wide namespace and its owner/target metadata. Extend owner verification to bind action_key and object_type_id, which existing PayRun payload_digest omits and only the ontology wrapper checks. Exact binding also includes protocol/hash version, authenticated Account/CompanyActor attribution, immutable target, normalized parameters/reason, relevant expected revisions and sealed attempt/context. Do not stamp wage or tax receipts falsely as ObjectKey::PayRun; extending typed object/action/receipt registration for those entities is W04b schema work. No route is activated until that registration and dispatch ownership exist.
Preserve existing legacy receipt algorithm and classification. New NP1 fingerprints use a separate domain tag and a documented typed canonical encoding; no rewriting old digests. wire-candidate.json fixes scalar parsing and receipt fields; exact per-command digest vectors and object/actor discriminants are W04b remaining proof. Hashing arbitrary JSON serialization or a preview label is not accepted.
Idempotency sequence: authenticate current account/session -> current authorized discovery/read of command/receipt without leaking a hidden target -> identify existing receipt under exact Company+command key -> compare stored owner/target/actor/action/wrapper/payload identity -> if committed, return authorized immutable result with separately evaluated current status; do not reconsume gate, require old source currentness or re-run obsolete business preconditions. A replay requiring more disclosure than presently allowed returns an authorized restricted receipt view or uniform not-found; it never reexecutes to get a new view. Unauthorized lookup does not reveal collision/actor/name. New request with same key and different exact binding is409 command_conflict only after disclosure allows that distinction.
If no receipt is observed, it is not proof of no effect while a concurrent transaction is uncommitted. Acquire the relevant ordered guard/fence set and authoritatively recheck receipt before rejecting current NEW-EFFECT authority, current assignment/custody eligibility or source validity. Earlier participants fence/collect facts only on this ambiguous path. If a concurrent identical command committed while these locks were acquired, return its current-disclosure-filtered historical receipt despite intervening execution-permission loss. Only authoritative absence proceeds to authorize_new_effect and business checks. If a historical control binding was removed, use its protected retained receipt/command fence and current disclosure; do not require a new assignment or fabricate an active binding merely to read history. Exact physical retention/fence keys remain W04b. Then proceed or wait for bounded reconciliation. Same committed key under another transport must recover same result. A client timeout is UNKNOWN until owner receipt or established rollback; an audit/projection/HTTP failure after commit cannot authorize a second effect. Outbox/read-model repair has its own idempotent projection key.

TX1.3 Total-order obligations
Retain WA1/WA2/GO1 prefix; never replace it with candidate02's shorter run-first order. Acquire only relevant subsets in this relative order:
1 Group identity/topology; 2 sorted Account/security/session guards; 3 sorted target/provider membership/policy/qualification; 4 sorted RoutingAccountControl (SHARE for nonterminal business effect, EXCLUSIVE up front if completing/releasing/assigning); 5 Company coverage/definition and applicable HandoverPlan SHARE then sorted WorkItem assignment guards; 6 Group operation parent SHARE; 7 sorted Company draft/child/attempt and command execution fences; 8 workflow run/node guards; 9 domain period key, sorted run heads, sorted source-scope/source heads; 10 exact governance gate bindings/consumption; then already-owned writes and completion/outbox/receipt.
References are discovered before locking then validated under locks. Changed required set => rollback and replan, never acquire an earlier lock while holding later ones. No SHARE->EXCLUSIVE upgrade after task locks. Group stop acquires parent EXCLUSIVE without child/domain locks; HandoverPlan stop acquires its Company plan EXCLUSIVE without task locks. They stop future execution and preserve past outcomes. No waits on humans or another Company inside a business transaction.
Payroll mutation and any task-terminal/capacity/draft-attempt finalization share this transaction. Source modifications participate in corresponding earlier source guards before their own fact writes. Period-lock writers and staging use existing lock_period_lock_key, not a separate mutex. Exact physical keys, PostgreSQL grants and complete participating-writer enrollment are W04b; conceptual ordering alone is not runtime deadlock proof.

TX1.4 Atomic gate and failure outcomes
Current ontology projected path consumes governance before dispatch and has post-owner audit work. For enrolled owner-managed actions it must instead let the payroll executor perform the exact-bound governance consumption, payroll effect, required owner audit, command receipt and participating completion in one transaction. The wrapper may render or repair its projection after commit, but cannot consume another gate or require successful postcommit audit to call the domain result committed.
Governance-owned extension must bind the approval to exact Company, requestor verified identity, action/wrapper/target, command/payload digest, input/calculation/proposal and current policy requirements, with expiry/revocation/independence proof from AC1. Calling current kind/target-only consume on the shared connection is necessary but insufficient. Exact governance schema and function signature are part of W04b; no pre-consumed legacy approval can substitute for this proof.
Preflight calls the same current guard/profile/state evaluation and the non-consuming gate check. It writes no business data, consumes no approval and reserves no task. Execute rechecks under locks. Accepted preflight is advisory; a new denied/stale execute preserves allowed input and offers the owning repair route.
Before commit failure: rollback all gate/effect/receipt/completion together. After commit lost response: historical receipt recovered, current disclosure applied. Driver cannot establish rollback: retain UNKNOWN, attempt/capacity pins; no new command ID. Only established no-effect transient serialization/deadlock/connection recovery retries use the same binding; max3 transaction conflict retries, then paused recovery. Policy/source/validation failures wait for correction, not exponential retry pretending they are outages. Source changed after old success: return old historical receipt plus current stale status, not replace success with failure.

TX1.5 Authority checks are actual execution inputs
Existing Cedar engine is real; workflow authz_guard still emits NotConfigured under its LegacyOnly coexistence path. Enrolled actions need the real current bundle, typed subject/resource facts, per-action and mandatory-field authority through their shared guard protocol. No job title, role string, task assignment or company membership alone is permission. No raw bool trusted from UI, no globally switched mode with absent integration, and no legacy fallback after Cedar denial. Current policy revision/freshness must be fenced with participating policy writers.
Permissions distinguish discover/read-property/read-derived/action/history/replay and required decision evidence. Server-owned complete scheduling/input analysis does not grant caller hidden line details or totals. Filter returned DTO, error links, field paths, receipt refs, HTML/data-* and hydration before serialization; permitted action only if all mandatory input/evidence can be disclosed. No-store/private sensitive responses and current disclosure on asynchronous notifications. Error codes are sanitized to uniform not-found where disclosing a code reveals a hidden object.
This chooses composition and behavioral obligations; it does not declare Cedar schema, identity enrollment, Group-control SQL ACL or source-guard implementation complete.
