Actual inspected API process has a console_rt pool max6 and three command pools max2 each: console_leave_cmd, console_ontology_cmd, console_platform_force_cmd. They are created once in AppState and cloned into adapters; clones must not allocate more pools. Current API bound12 per replica,24 for at most2 replicas including rollout, is within17's allocated40 serving connections; unused16 are headroom, not automatic allocations. Worker/migration/operator/monitor/reserve deployment mapping remains17/F04/F08 and must account for every actual process. No secrets or new connections are read/created here.
Proposed console_owner_commit_writer is NOLOGIN, NOSUPERUSER, NOBYPASSRLS, NOCREATEDB, NOCREATEROLE, NOREPLICATION. No LOGIN/runtime/generic writer role may SET ROLE/inherit it. Functions have fixed search_path=pg_catalog, row_security=on, schema-qualified references, bounded typed arguments, no dynamic SQL/caller-chosen identifiers and only required table privileges. It owns no schema or table and cannot replace registry/policy/DDL. Migration owner remains trusted separately. Same-transaction default-ACL revocation is mandatory under0031. Review actual pg_auth_members SET/INHERIT and default ACLs, function ownership/EXECUTE and schema CREATE before enrollment; NOLOGIN alone is not confinement.
Public command credential console_ontology_cmd gets EXECUTE only on fixed registered outer lock/read/probe/commit functions. Raw tables, raw source mutation, native money/receipt INSERT, generic instance helpers, internal pin/gate/attempt/work helper EXECUTE remain denied. Functions that only lock/read must have no mutation side effects except transaction locks and return only the trusted executor's bounded internal facts. Client has no database credentials. This capability is trusted internal execution, not per-human Cedar enforcement by PostgreSQL.
Each outer owner commit function validates its exact owner/action/type/schema/protocol/Company/actor/attempt/expected binding and dispatches only its compile-enrolled mutation shape. Do not expose a commit_any(table,rows) helper or make a generated callback list executable. Its prepared inputs are produced only by the authenticated trusted Rust owner; ordinary REST never accepts prepared kernel results or privileged computed validity fields. SQL validates source identities/state/CAS/bounds/immutable header-member completion and command equality, while qualified source semantic correctness and kernel arithmetic remain Rust trust. A compromised trusted executor remains within the documented compromise boundary.
Private SQL participants grant EXECUTE only to the confined commit writer; same writer DML is confined behind outer functions from the LOGIN caller. Generic existing console_ontology_writer cannot call them. Protect ont_instances/revisions/links for owner-bound types with row backstops rejecting all runtime/generic-definer current_user paths except the new confined writer; source-controlled writes still validate correct object/action registration in their entrypoint. One admitted writer role is not itself a type or human authorization. Direct migration/admin operations remain separately controlled trusted maintenance and source-generation/enrollment obligations, not a runtime escape hatch.
Any legacy alias reaching an enrolled Company/type/run/source delegates the same owning executor or fails before effect. Explicitly v1 leave decide without expected_version receives precondition_required for enrolled records; it cannot infer a latest version. V2 still needs exact command/attempt/Cedar/source contract, not just a version. Legacy leave SQL command grant may remain for nonenrolled data only after its entrypoint rejects enrolled targets. Old clock handler, Docs verify/dispose, generic instance links/revisions, payroll projected gate preconsumption, raw receipt INSERT and higher-version money INSERT are all enrollment blockers until redirected or DB-denied. Hiding UI actions does not count.
Activation is granular by the existing17 admission manifest, with dependencies: current Account+actor/receipt registration; compiled owner/type/codec binding; all reached callers/SQL triggers+functions updated; guards preinitialized; restricted persistence participants+retention pins; exact source storage/attestation reader; compatible projections and explicit measured budgets. No source-only toggle admits an action with a missing attempt/gate/work participant. Missing source/provider capability leaves affected path unadmitted with repair/status; it is not a production success oracle.
Rollback after any enrolled write uses compatible readers and pauses new writes; it preserves permanent Account cutover, owner bindings, receipts, source heads, pins, unknown attempts and historical formats. Do not delete bindings to make generic writers work again, reset generations, drop FKs or resurrect old source/authorization.20 chooses the execution/capability protocol and owner controls; all exact body implementations, full13-19 physical graph, real role/provider setup, recovery and execution proofs remain explicitly incomplete.

Shared LOGIN blast radius: EVERY process/holder of console_ontology_cmd can call the newly granted outer finalizers and is therefore trusted to supply server-validated Account, Cedar and prepared result facts. Withholding private helpers from console_ontology_writer does not isolate holders of the shared LOGIN from each other. This packet chooses shared existing API ownership for the pilot, not unproven process isolation.
