Source19-v1 payload bytes and their hash tags remain unchanged. A source command may name an exact acknowledged common draft revision through SourcePayloadRef20 rather than embed a64KiB source payload inside another64KiB command. Ref includes Company, draft/instance ID, immutable revision UUID+version, exact input schema ID+revision, and source19 payload digest. Server derives it from the locked retained revision; caller cannot select an unrelated draft, schema, action, target, actor/custody or owner. A ref is neither a capability nor proof of complete validation. The immutable submitted source payload is copied/adopted into its owning15/19 source record before releasing private draft pins. No second editable revision sequence: common instance revision stays the edit history, source admission/native fact is the business effect.
Normalize complete source payload from the exact typed draft attributes under its registered pure owner codec. Calendar normalized payload depth7 fits the14 common revision envelope at8; source19 semantic envelope also fits8. Large command bodies use the reference form. Form editors send bounded one-field/one-item common draft.save patches selected by immutable registered field IDs and stable weekday/date/item keys. For example a day-plan replacement has command/body/value/duties/duty/breaks/break nesting7, preserving coupled start/end/break validation; it is not a deeply nested whole-calendar replacement. Owner codec maps exact declared field/item to common attributes and validates the full new head. Unknown keys/paths, arbitrary JSON pointer mutations, cross-action fields, partial hidden overwrite and oversize values are refused. Coalescing can prepare a single coupled item change; a multi-item operation requires an explicitly registered bounded patch shape and atomic validation, not sequential partial saves masquerading as one command. No loosening of14's64KiB/depth8 boundary, implicit schema coercion or browser-persisted sensitive draft.
Input schema registration includes a literal maximal supported field-group patch and normalized revision envelope size/depth witness. This packet supplies a calendar example, not a proof every proposed13-19 command codec fits; other closed source/action wire contracts and generation remain F01 outputs. Preparation and network separation
For each required Docs original/derivative/package, allocate server-owned object/copy identity through the existing Docs owner and typed source upload subject, preserving original bytes and lineage. No fake WorkOrder/user/Employment. Capture exact bounded source snapshot under relevant guards, release transaction, decode/build/read exact immutable versions through storage outside locks, and persist a trusted READY version attestation through its own Docs owning command. Optional provider version or key-only HEAD cannot mint READY. Bind provider/bucket/key/version/bytes SHA/size/format/current scanner and retention proof as15 requires. Actual versioned GET must extend the existing storage seam; concrete versioned HEAD/DELETE are reused.
Preparation is an explicit registered owner Action producing staged artifacts and draft input references, not a new approval engine or a side effect of GET/preflight. It may complete across separate transactions because it publishes no business source. Final source19 event/day/member package refs must exist BEFORE final command seal/gate fingerprint; execution cannot append freshly uploaded refs to an already sealed attempt. If preparation changes, save a new current draft revision and reseal after conclusive old-attempt cancellation. Staged uploads with lost response are reconciled by exact Docs command/copy identity; they are never interpreted as published coverage. Source page can show preparation progress through existing draft/action status and preserve acknowledged input.
Final publication first probes authoritative receipt/provenance (OE20 P1). Matching historical success needs no source preload or new artifact preparation. Only an eligible absent effect proceeds through P1a: release probe locks, preload exact-version decoded bytes outside locks, then restart the full fence/receipt/provenance phase before source validation. If storage fails, re-probe receipt/provenance before returning a new-effect blocker; never infer absence from unavailable data. Under final LO20 guards publication re-resolves current source semantics, current attestation/credential/profile state and exact input head. Preloaded bytes are usable only if exact attested identity+hash and registered decoder build match locked current refs. Any changed required source/attestation/permission blocks or restarts before effect; no network inside final transaction. An unrelated epoch can pass after full semantic re-resolution. Current source existence/guard checks and decoder trust are not delegated to browser files.

Atomic adoption
Same owner commit entrypoint inserts complete source/native record, adopts/pins each exact required immutable payload/artifact through the shared retained-unit/Docs owner, writes mandatory audit and single command receipt, then finalizes common attempt/work. Missing pin/hold/unit/ref, mismatched adopted bytes, UNKNOWN predecessor effect or failing deferred constraint rolls back all. Domain adoptions must be independently readable under current domain disclosure after private draft payload disposal; keeping a lineage-only UUID/hash is insufficient. Draft pin release only follows verified adoption in that same transaction; other domain/qualification/unknown-attempt pins stay intact. Receipt identity/tombstone survives source payload retention policy, without copying private salary/notes into generic audit.
Current PgDocsStore methods opening with_org_conn/with_audits are not borrowed participants. Extend its existing private helpers to accept the owner's borrowed PgConnection and invoke them through confined SQL persistence where privilege is required. SQL wrapper owns fixed statements and may not accept arbitrary table/key SQL. Disposal, provider issuance, independent journal and restored-authority admission remain F03-F07 prerequisites; until proven, affected physical cleanup routes refuse retained enrolled source copies. This is containment plus explicit unfinished work, not an implemented deletion service.
