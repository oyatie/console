업무는 실제 담당자를 따라가고,
기록은 해당 법인에 남는다.

한 tenancy에 6개 법인이 있어도 각 법인마다 인사담당자와 현장관리자가 있을 필요는 없습니다. 전사 공용 인력, 본사 사업장, 다른 법인의 사업장·부서가 정확한 권한과 업무 범위에 따라 운영을 맡을 수 있어야 합니다.

설계 후보 · 구현 승인 아님

두 독립 검토자가 준비 이력 보완 후 범위 내 수락했습니다. 검토 SHA: 175813e042c9240b329214046da3bb953a141890. 전체 설계나 구현 승인은 아닙니다.

50개 시나리오와 14개 화면 상태는 실행 가능한 테스트가 아닙니다. 제품 코드·SQL·배포를 변경하지 않았습니다. 첫 실행 증명 범위는 선택한 법인별 기존 급여 초안 계산이며, 결재 결정·지급·일반 자동 인계는 별도입니다.

사용자가 제시한 조직을 실제 사례로 다룬다

사례Console의 처리
A·C 법인에는 로컬 인사담당자가 없음전사 공용 담당자의 A·C 대상 권한으로 수행. 가상의 A·C 직원이나 자회사 계정을 만들지 않음.
A 현장에 관리자가 없고 A 본사에서 담당본사도 사업장으로 표현. 해당 현장 업무 범위를 연결하고 필요한 정보만 제공.
A 현장을 B 법인의 사업장·부서가 담당법인 식별자를 포함한 담당 관계를 연결. A의 업무는 A의 소유자가 처리하고 B의 소속·근무 장소는 그대로 유지.
같은 담당자가 A와 C를 서로 다른 범위로 지원A의 넓은 권한이 C로 번지지 않음. 법인·대상·정보별로 각각 판단.
사원에게 대표이사보다 넓은 시스템 권한이 있음허용된 시스템 기능은 사원이 사용하고 대표이사는 제한될 수 있음. 직함으로 급여 열람·결재·법적 서명 권한을 추론하지 않음.
같은 직함을 가진 두 사람이 다른 일을 담당각자의 실제 권한으로 화면과 액션 구성. 미리 정한 직무 역할을 강제하지 않음.

공용 부서가 지원한다는 관계와 개별 업무의 책임자를 구분합니다. 하나의 원자적 업무에는 한 명의 책임 Account가 있어야 합니다. 담당 후보가 없으면 권한 있는 수동 배정 경로가 필요하며, 자동으로 대표이사나 상위 관리자를 선택하지 않습니다. 구체적인 자동 배정·인계는 다음 B04에서 이 사례들을 기준으로 설계합니다.

전사 실행의 입력 경로

  1. 전사 업무 화면에서 허용된 법인과 기존 급여안을 선택합니다.
  2. 각 법인의 준비 상태와 필요한 연결 정보를 같은 화면에서 확인하고, 문제가 있는 입력은 기존 업무 폼에서 수정합니다.
  3. 실행할 범위를 확인합니다. 준비된 일부만 선택했다면 그 범위 그대로 기록합니다.
  4. 선택한 법인·대상·입력 버전을 고정하고 저장한 뒤, 각 법인의 소유 Action이 독립적으로 계산합니다.
  5. 성공한 결과는 유지합니다. 일시적 오류는 같은 요청으로 확인·재시도하고, 입력을 바꿔야 하는 법인만 검토한 후속 작업으로 이어갑니다.

전사 화면의 추가 권한이 없어도 특정 법인의 업무를 직접 처리할 권한이 있다면 그 법인 업무 화면은 사용할 수 있습니다. 화면에서 실제 대상 법인을 분명히 표시하고 다른 회사의 입력을 섞지 않습니다.

일부 실패해도 전체를 다시 하지 않는다

상황보장
6개 중 3개 성공, 1개 오류, 2개 미실행각 결과를 유지. 전체 실패나 전부 완료로 합치지 않음.
응답을 잃어버림같은 명령의 원래 영수증을 확인. 새 ID로 중복 계산하지 않음.
입력·계산 근거 변경영향받은 대상만 새 검토를 거친 후속 작업. 원래 결과는 이력으로 남음.
사용자가 중단이후 실행을 차단. 이미 완료된 계산을 임의로 되돌리지 않음.
도중에 세션·권한 종료아직 실행하지 않은 대상은 재확인 대기. 새 세션에서 같은 사람이 명시적으로 재개.
선택 이후 새 법인 추가기존 작업에 자동 편입하지 않음. 선택 시점의 범위를 그대로 유지.

전사 관리도 최소 권한을 따른다

전사 작업을 보는 권한, 개별 법인을 발견하는 권한, 진행 상태를 보는 권한, 금액을 보는 권한은 각각 다릅니다. 일부 대상만 볼 수 있다면 허용된 결과만 보여주며 숨겨진 법인의 수·실패 여부·진행률을 누출하지 않습니다. 전사 권한 하나가 모든 법인의 급여 권한으로 확대되지 않습니다.

저장·진행·중단에는 Group 소유의 최소 제어 정보가 필요합니다. 금액과 실제 입력은 각 법인에 남고, 실제 쓰기는 해당 법인의 기존 소유 계층에서만 일어납니다. 새 서비스·직급 역할·혼합 법인 급여 저장소를 만들지 않습니다.

남은 증명

Group 제어 저장소의 좁은 SQL/권한, 현재 정책과 취소의 잠금 경계, worker의 세션·세대 검증, 실제 처리시간과 복구는 이후 승인된 테스트/구현에서 증명해야 합니다. 일반 자동 인계 B04, 나머지 화면 B07, 금액 공개·이의 처리 B08, 전체 설계/test SHA 승인도 남아 있습니다.
