CA16 — Examples inform a general object/action design; they do not define a special pipe
User correction applies throughout Console, not just transfer: workload, instruction and absence are illustrative reasons. They are neither exhaustive action variants nor separate engines/screens. Generalize the useful operation across typed objects; do not generalize an example's incidental process into a universal requirement. This packet explicitly refines WA2's separate instruction/self-request presentation into contextual entrances to one transfer composer and protocol; historical evidence is not overwritten.
Use common registered Action -> policy-derived input/evidence contract -> common versioned draft -> optional exact review/gate -> owning effect -> immutable receipt/history. Navigation/task/detail/sheet cells and future communication objects may point at the same Action/target; the input path cannot change authority, idempotency or state transitions. Runtime reaches a closed registered owner, never arbitrary URL/function/plugin code. Operation-specific domain validation remains where its invariant lives. Reuse does not make an approval grant, a completed decision, work assignment and a monetary effect the same state change.
Objects/relations hold variable business configuration where identity/history/policy matter: WorkDefinition, WorkCoverage, RoutingRule, optional ReasonRef, source/instruction/evidence refs. Engine enums describe actual finite state/protocol semantics, not employee titles, example industries or human motives. ReasonRef plus optional narrative records context; no reason-name switch grants authority, changes availability, selects permanent transfer or skips a gate. Registered typed facts and existing policy decide those independently. Absence sources can update real availability, while a busy person's reason alone does not declare them absent. Future reasons do not require a new transfer API/state machine.
Manual and automatic initiation call the same owner Action. A workload principal has a scoped mandate to select/prepare/execute only admitted operations, not a human identity or unlimited salary rights. Input is prefilled from related objects; show only necessary missing decisions and surface required notes/evidence at that step. Manual correction can use the same typed fields/current guards; no hidden bypass. Reusable controls: object selection, current actor/scope, evidence and changes, exact preview, confirmation or request, durable outcome, repair/resume. Omitted controls must not omit required information. Read-only preview does not create a task or consume approval.
Concrete reuse choice: existing governance request/decision facts serve both business review and optional execution permits with distinct typed purposes. Payroll owns required review membership and deterministic completeness, not a second general approval engine. Workflow owns accountable work and transfer, not a second payroll decision writer. Docs owns evidence, identity owns Account/human/entitlement, Group owns narrow control accounting. First proof uses payroll and related work; these are owner registrations, not hardcoded restrictions on the common mechanism. Additional owners need their real invariant/proof before activation, not duplicated plumbing or hypothetical extension points.
