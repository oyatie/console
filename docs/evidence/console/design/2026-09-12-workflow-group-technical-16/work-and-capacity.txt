WC16 — One workflow-owned assignment/transfer protocol
WC16.1 Reuse and physical identity
Reuse workflow_waiting_tasks (org_id,id) and workflow runs/nodes/outbox. Existing claim_waiting_task locks task but loses the app's parsed idempotency_key before its command; decide_waiting_task uses legacy idempotency-key-only replay and self-approval exceptions. Runtime guard is LegacyOnly/NotConfigured. These are inspected gaps, not newly implemented fixes. Enrolled aliases must normalize CCF1 and delegate the owning protocol or refuse. All waiting-task INSERT/terminal/finalize/node paths join it; raw task creation cannot leave absent assignment control, terminal cannot strand a charge. Assignee/claimed/completed actor FKs migrate to CompanyActor under AS1, without inventing an Employment.
Add workflow_work_controls one per existing task: current task revision, current assignment epoch, immutable WorkDefinition ref, current coverage/target binding and enrollment. Add workflow_assignment_revisions keyed Company/task/epoch: assignee Account nullable, state UNASSIGNED|ACTIVE|PAUSED|TERMINAL, exact definition/coverage/target/incarnation/proof refs, validity/obligation intervals, charge Group+task+epoch, responsibility intent and original responsibility binding, causal receipt. Facts append only; control CAS points to current. Task business status remains separate. One current accountable person per atomic task; a team coverage is a candidate relationship, not shared accountability.
Governed WorkDefinition, WorkCoverage, RoutingRule and optional ReasonRef use existing common object type/action registration and immutable instance revisions from14. Workflow owns validation/publication through its registered Actions; generic instance CRUD cannot bypass controlled types. No new editable revision store for each configuration kind. Definitions bind existing workflow definition version where applicable; no new parallel graph interpreter. Coverage identifies target scope plus Account/provider Company+OrgUnit, finite applicability and provenance. Legal employer, hierarchy, physical workplace, coverage and action/field permission remain independent. Current membership/policy proofs are resolved through owning helpers; never query provider salary/personnel tables by widening target RLS.

WC16.2 Common transfer input and execution
Use one work.transfer request bound to a workflow-owned TransferPlan whose editable input is a common draft. Inputs: exact task refs and expected assignment epochs, per-task nominated Account or registered routing-rule ref, TEMPORARY|PERMANENT responsibility intent, effective interval, optional ReasonRef/context refs and bounded narrative. Intent affects duration/return policy, not the reason label. A missing permanent end date does not authorize unbounded task obligations; each task has its own bounded definition interval. Partial workload is a set of tasks; splitting a task requires its owning definition's exact disjoint output split and fenced parent completion, never PARTIAL_SHARING.
workflow_transfer_controls binds exact common revision/digest and plan state DRAFT|REQUESTED|AUTHORIZED|ACTIVE|STOPPED|COMPLETE, epoch and original actor/mandate; workflow_transfer_targets stores immutable activated tasks/expected epochs and target-selection binding, with receipt-derived outcome refs. Max20 selected tasks/100 moved units is the current bounded execution manifest default carried fromWA2, not a reason-specific rule. Larger manual selections create explicit independently acknowledged chunks, not implied all-chunk atomicity. Plan drafting preserves selection; unauthorized nomination is not a grant. Current policy decides direct execution versus request for authority/optional permit. Same composer/action for all entrances, with required contextual information present.
Each activated task transition commits independently in ONE target Company transaction. After current fenced fact collection and authoritative command-receipt recheck: current issuer/workload mandate, recipient task/action/evidence feasibility, actual capacity/availability/qualification and valid scope -> control/plan/task/Group-parent/draft/attempt fences -> conclusive prior effect reconciliation -> common owner cancels old READY no-effect attempts only where allowed -> rotate assignment/custody epochs -> transfer charge -> assignment revision/control + metadata receipt/audit/outbox. Source author and actual requester/executor remain distinct attribution. Sealed actor identity is immutable; successor intent must be new and explicit. Private drafts remain private; work-bound drafts move only as allowed projections, never all mailbox/storage data.
Changing assignment when it is a Cedar operand takes earlier Company authority EXCLUSIVE up front. Proposed-assignment feasibility is a policy-owner internal probe bound to exact candidate/task/next epoch, admitted only by pre-existing assignment-conditioned policy. Recheck real actual assignment before commit. No exported evaluate-as-user endpoint. A successful old receipt is reconciled under current disclosure before rejecting new-effect eligibility; loss of employment/assignment/session does not rewrite it. UNKNOWN retains assignment/capacity/pins until receipt or conclusive rollback/no effect. For Group-bound child work, stop parent in its separate transaction before per-Company cleanup; never acquire parent EXCLUSIVE while holding task/draft locks.
Stop plan: policy guards then plan EXCLUSIVE, no capacity/task/domain locks. Advance STOPPED epoch, preserve prior transfers, no automatic rollback. Task effect holds plan SHARE through commit; stop waits admitted effects, then fences later ones. Active content is immutable; changes require stop + explicit successor selection. Completing plan is later exclusive control reconciliation of exact receipts, never a lock upgrade in a task transaction. A temporary end schedules reevaluation through the same action; no timer blindly returns work or restores old rights. If original worker now lacks eligibility, keep actual ownership truthful and create actionable pending transfer. Future responsibility coverage changes use their own versioned relation, not unnoticed changes to the plan's fixed task set.

WC16.3 Group capacity ownership and reconciliation
Group routing controls have group_id/account_id, current capacity profile/availability revisions, used_units, fairness sequence and integrity state. Group-owned immutable capacity profiles hold configured positive integer limits/validity; availability revisions hold minimal Account/interval AVAILABLE|UNAVAILABLE|UNKNOWN/source version only, never medical reasons. group_work_charges keyed Group/targetCompany/task holds current epoch/account/units/status and assignment receipt binding; historical charge changes are retained as append events. Protected helpers borrow the same connection as ONE Company's workflow mutation. They validate current target context/membership for positive admission, exact charge/task/epoch binding, authority and limit; no arbitrary counter API or runtime raw access. Used units equals active charges, including PAUSED/UNKNOWN; no lease/TTL expiry releases work.
Candidate enumeration/ranking follows WA1: explicit feasible nominee, configured coverage priority, checked integer projected utilization, fairness sequence then stable Account ID. Complete scan limit2000 candidates with100/page, source-version-bound advisory checkpoint; limit/drift means MATCHING_INCOMPLETE, not no eligible worker. Commit rechecks current feasibility; global optimality not promised. Max3 conflict retries, then durable repair; source changes/manual retry may start a new bounded generation. Anti-churn and configured per-task cooldown apply to automation regardless of reason. A reason alone never triggers reassignment. All no-candidate or missing-config outcomes retain a supervised unassigned/blocked task and typed manual repair path.
Availability source owners synchronously invalidate/update the routing control watermark before new effects can use obsolete availability; async outbox schedules work but is not the revocation fence. All source changes predeclare Group/Account/control locks ahead of Company/source locks; if impossible, affected enrollment stays blocked. Manual authorized availability correction is versioned source evidence, not a transfer override. Counter/profile reduction cannot remove charges; over-capacity rejects positive net admission and permits release/transfer out. Task terminal actions take EXCLUSIVE capacity lock from entry; ordinary nonterminal action takes SHARE.
Company membership removal/re-add creates a new incarnation; old work charge retains its original Group binding. Historical release-only helper uses retained anchors and exact terminal/transfer receipt even when current membership is gone. It can decrease/close that exact old charge only; cannot assign in the old Group, recreate grant or remove unknown work. Old and new Group guards/controls, when both required by an explicit migration/transfer, are declared and sorted before Company locks; no automatic cross-Group staffing is enabled. Periodic bounded reconciliation compares controlled charges with owner task receipts per Company; discrepancy pauses positive admission, opens repair, never treats a guessed counter rewrite as proof.

WC16.4 Configuration fence and bounded controls
The conceptual Company coverage/definition guard is the existing proposed company_authority_guards row from13, not another new lock table. Registered workflow configuration/current coverage changes increment that authority epoch under EXCLUSIVE; consumers hold its earlier SHARE/EXCLUSIVE and use immutable exact common revisions. This fences new/absent coverage predicates as well as current heads. Current work refs must agree before task effects; source edits cannot silently reinterpret an existing definition. Common editable draft/head locks still follow14 at class7; immutable already-published configuration refs need no late current-head mutation.
