Console / 구현 전 설계 검토 / B06 + 일부 B07

초안도 객체다.
변경 이력은 공통 엔진이 맡는다.

사용자의 정정은 “Git 서비스를 붙이자”가 아니라 “초안의 변경을 효율적으로 추적하자”입니다. 초안부터 동일한 객체·정책·버전 체계를 사용하고, 업무의 유효한 내용은 소유 Action을 통해서만 바뀝니다.

설계 후보 · 구현 승인 아님

두 독립 검토자가 세 수정점의 해결을 범위 내 수락했습니다. 검토 대상 SHA: ff914047e1ff163297f6a6fff30bf1315086241a. 전체 설계 합의나 구현 승인은 아닙니다.

50개 시나리오와 18개 화면 상태는 실행 가능한 테스트가 아닙니다. 제품 코드·마이그레이션·테스트는 변경하거나 실행하지 않았습니다. 실제 민감정보 활성화와 전체 구현 준비 완료를 뜻하지 않습니다.

사용자가 경험하는 흐름

순간사용자에게 보이는 것시스템이 보장할 것
업무 시작해당 업무의 저장된 초안 재개같은 의도의 중복 초안 방지. 개인 신청과 담당 업무의 접근 범위 구분.
입력저장 중 → 서버에 저장됨연속 입력을 묶어 저장. ACK 전에는 저장됐다고 표시하지 않음. 미완성 입력도 보존.
두 탭 수정독립된 수정은 유지, 충돌은 해당 입력에서 해결같은 기준 버전 검사. 금액/통화처럼 결합된 입력은 임의 병합하지 않음.
이력 보기허용된 변경 내용·작성자·시점 비교과거 버전도 현재 권한 적용. 전체 원본 이력을 브라우저에 보내지 않음. 이력 존재 자체의 열람 권한이 없으면 목록은 제한하고, 별도로 허용된 제출 버전은 조회 가능.
복원선택한 이전 값의 변경 미리보기 → 저장새 revision을 추가. 숨겨진 다른 값은 유지. 결재·급여 실행 없음.
상신정확한 입력 확인 → 제출 결과검토 revision 고정. 효과와 영수증을 함께 확정. 결과 불명은 확인 중으로 표시.
담당자 변경후임이 허용된 저장 입력에서 계속전임자 늦은 저장/실행 차단. 개인 초안 자동 공개 없음.

객체의 정체성은 업무 의미에 맞춘다

새 신청서: 업무 소유자가 그 생애주기를 지원한다면 같은 객체가 초안에서 제출 상태로 진행할 수 있습니다. 제출된 현재 내용이 공개돼도 개인적인 작성 이력은 자동 공개되지 않습니다.

기존 계약·급여 변경: 원본에 연결된 변경안 객체를 수정합니다. 첫 급여 적용은 이 방식입니다. 저장은 변경안의 버전만 추가하고, 실제 급여 데이터는 기존 급여 Action만 바꿉니다. 하나의 변경안이 여러 결과 객체를 만들 수도 있습니다.

“다음 달부터 적용”은 업무 효력일입니다. “방금 저장”과 섞지 않습니다.

기존 엔진에서 가져올 것과 보완할 것

확인한 코드판단
draft 객체 생성, 전체 revision, 시점 조회, hash chain공통 저장·이력 구조 재사용. 별도 초안 history store 없음.
Action 경로의 기준 버전 검사와 중복 명령 영수증보호를 공통 소유 계층으로 모아 SSR/REST에 동일 적용.
현재 객체 권한 확인 후 전체 과거 이력 반환초안에는 부족. revision/field별 공개와 내부 무결성 검증 분리.
전체 속성의 감사 snapshot 및 raw receipt민감한 초안 값을 중복 공개하지 않도록 최소 영수증·허용 DTO 필요.
필수 속성·거친 타입 검증typed incomplete cell 지원과 깊은 검증 필요. 업무 확정 검증은 약화하지 않음.
이력 삭제 금지 trigger보존 만료의 물리 폐기는 별도 설계 공백. 일반 삭제 권한을 열지 않음.

효율은 기존 구조에서 먼저 얻는다

변경된 property만 요청하고, 의미 있는 저장만 revision으로 남기며, 비교할 두 버전만 읽습니다. 초기에는 공통 엔진의 전체 snapshot을 유지합니다. 최근 20개를 넘었다고 이력을 지우는 제안은 철회했습니다.

예시 가정으로 100명이 8시간 동안 5초마다 저장하면 하루 576,000회입니다. 회당 4 KiB면 payload만 약 2.36 GB이며 index·WAL·backup 비용은 별도입니다. 실제 pilot 예측값은 아닙니다. 저장 빈도·no-op·지연·보존 용량을 측정한 뒤 필요할 때 공통 엔진의 변경분/체크포인트 저장을 검토합니다. LLM 해석은 필요하지 않습니다.

아직 닫히지 않은 공백

개인 초안의 보존·물리 폐기와 백업 처리, 독립적인 무결성 기준점 및 복구 권한은 별도 세부 설계가 필요합니다. 기존 business chain의 삭제 방지를 약화해서 해결하지 않습니다. B03 전사 실행, B04 일반 자동 인계, B07 나머지 화면, B08 금액 공개·이의 처리도 남아 있습니다.

전체 설계 합의와 명시적 design SHA 승인 → 독립 검토된 executable test SHA 승인 → 구현 순서를 유지합니다.
