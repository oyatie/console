전사에서 시작해 원 사실까지 이어지는
급여 입력·계산·결재

1개 tenant Group · 6개 법인 · 총 2,000명 · Console 운영

이번 후보는 실제 기존 경로를 재사용하는 설계다. run 생성과 canonical 재시도는 이미 존재한다. 핵심 추가 작업은 native 입력을 run 계산에 연결하고, 전사 실행·정정·결재의 보장 차이를 닫는 것이다. 아직 승인된 design/test SHA나 구현 완료가 아니다.
핵심 결정10개 화면9개 액션기존 상태8개 공백20개 수용 사례검토 자료

제품 의미와 기존 코드의 차이

기존 import 기반 roster/run 계산과 직접 입력한 계약급여의 개인 초안은 다른 흐름이다. 개인 초안은 월 기본급·보험 등을 보여주지만 원천징수 미산정으로 순지급액이 없고, 시급제는 차단된다. 이를 완성된 전체 급여로 표시하지 않는다. 현재 canonical port의 생성 receipt는 상관 ID인 run_id와 실제 조회용 draft_run_id를 구분한다.

전사 범위는 현재 membership resolver 및 법인별 인가를 재사용한다. Group 멤버를 조회할 권한이 급여 권한을 뜻하지 않는다. group-admin delegated principal도 SUPER_ADMIN이 아니며 현재 법인의 feature grants를 따른다. 전사 묶음 실행은 별도 durable 조정이 필요하다.

결재 공통화는 화면 통일만으로 끝나지 않는다. 직접 payroll lifecycle은 계정 UUID를 비교하며, 제품 불변식은 서로 다른 자연인을 요구한다. 공통 Action에는 재시도 검증이 있지만 최초 실행의 승인 소비와 owner transaction이 분리돼 있다. 이 차이는 설계·테스트에서 닫아야 하며 기존에 완성됐다고 가정하지 않는다.

화면과 입력 경로

아래 경로는 제안된 Leptos 화면 경로다. 이 정적 문서는 클릭 가능한 업무 prototype이나 실데이터 앱이 아니다. 연락은 독립 workspace를 유지하고 객체 inspector와 작성 상태를 공유하지 않는다.

공통 액션과 기존 소유자

A01 · existing seams + new composition

전사/법인 읽기

진입: group_member_orgs → company-specific authorization → consolidated_read / owning read

소유자: console-platform-group + original read owners

입력: group_id, selected company_ids, period, paging

권한: membership visibility AND each feature/field policy; resolver alone is not payroll permission

재시도: read; as_of and partial/error semantics explicit

추가 계약: existing helper fails a combined read on member error; per-company result envelope is a reviewed extension, not existing behavior

A02 · existing canonical action

급여 run 생성

진입: POST /api/v1/ontology/actions/{action_key}/preflight and /execute; action_key is configured per object_type_id, not assumed equal to dispatch_target

소유자: PgPayRunPort; payroll.create_run

입력: object_type_id, title when required, command_id; params run_id/period_start/period_end/optional connector/job; checklist/four_eyes witnesses only as configured

권한: existing ontology gate + typed canonical query; current actor/scope; no direct port call from untrusted client

재시도: command_id+payload digest, same actor/action/type/current authority; navigate projected.draft_run_id

추가 계약: native roster source and source provenance adapter; changing correlation run_id per retry creates different natural key

A03 · existing REST write, extension needed for stronger contract

계약급여 원 사실 저장

진입: POST /api/v1/payroll/employees/{employee_id}/contract-wages

소유자: payroll adapter insert_contract_wage_in_tx + atomic audit

입력: effective_from,wage_kind,amount_won,monthly_standard_hours,source_note

권한: authorize_org_wide PayrollRunManage; employee belongs to armed org; future reference validation at owner

재시도: idempotency key not established on this route; response-loss reconciliation required

추가 계약: typed evidence/contract refs; consistent same-date revision and replay protection; avoid duplicating existing wage writer

A04 · new behavior required; proposed payroll.prepare_inputs

공식 계산 입력 고정/정정

진입: canonical action extension, path not yet published

소유자: existing payroll owner, not import or UI writer

입력: draft_run_id,expected_input_revision,typed immutable source refs; derived amounts verified server-side

권한: same tenant/company + manage + evidence-specific authorization; source verification is governed, not client boolean

재시도: canonical command receipt; immutable input revision; reject changed payload or stale version

추가 계약: native input manifest→roster→LineCalculationInput; imported and native facts normalize to same typed basis without fake import rows; exact schema migration needs reviewed test candidate

A05 · existing REST behavior

근태 마감

진입: GET /api/v1/payroll/runs/{id}/close-preflight; POST .../close-attendance {attest:true}

소유자: payroll lifecycle close_attendance_in_tx

입력: draft_run_id,attest

권한: read/manage gates respectively; execution rechecks current state/roster/period lock

재시도: existing state guards; repeated POST may 409; no fabricated shared idempotency claim

추가 계약: new immutable input revision must be bound at owner; source amendment/reopen policy requires explicit extension

A06 · existing REST calculation; common-action extension candidate

급여 계산

진입: POST /api/v1/payroll/runs/{id}/calculate

소유자: payroll lifecycle calculate_run_in_tx; same writer if canonical wrapper added

입력: existing bodyless draft_run_id; proposed expected input revision belongs in versioned extension

권한: current org-wide PayrollRunManage, locked current run state; future common-action policy cannot be bypassed by old route

재시도: existing duplicate uses typed 409; canonical create/submit/decide already differ; preserve compatibility intentionally

추가 계약: native sources + checked snapshot + authorization parity across entry paths; long job UI must use persisted job evidence if added

A07 · existing REST and canonical SubmitRun

상신

진입: canonical payroll.submit_run; existing POST .../submit

소유자: submit_run_in_tx once, port wraps receipts

입력: draft_run_id; proposed reviewed input/calculation/evidence digest

권한: same permissions and SoD binding across both adapters; CALCULATED and no open exceptions

재시도: canonical receipt vs direct REST state guard; documented compatibility convergence

추가 계약: exact snapshot/digest binding and common natural-person policy across every writable adapter

A08 · existing REST and canonical DecideRun

급여안 결정

진입: canonical payroll.decide_run; existing POST .../decision

소유자: decide_run_in_tx once, port wraps receipts

입력: draft_run_id,decision APPROVE|REJECT,reason required for REJECT; proposed exact submission revision

권한: SUBMITTED; current lifecycle compares user UUID; enforce current PRODUCT natural-person SoD across direct and wrapper paths

재시도: same command can replay accepted receipt when current authority permits; first projected failure may spend approval

추가 계약: account-level check is not proof of distinct natural people; release unchanged; no copying REJECT into leave law

A09 · new behavior required; not an existing group-wide write API

전사 묶음 실행

소유자: existing durable workflow orchestration if semantics fit; no business SQL in coordinator
