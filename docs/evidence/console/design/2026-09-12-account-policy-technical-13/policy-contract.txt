PA1 — Correlated capabilities, current policy and authorized projections

PA1.1 Reuse versus actual missing enforcement
Keep platform/authz's Cedar parser/strict validator/evaluator and restricted no-code residual compiler. Existing EffectiveFeatureGrant already preserves feature+permission+branch scope; do not call it an unsafe flat union. Its persistence lacks actual dated assignment bounds, and generated Cedar Role permits do not carry these custom grants. Existing object residuals really guard some ontology queries, but property_field_visible is not a production DTO sanitizer; raw attribute bags and declaration-only aggregate allowlists are insufficient. engine and authoring currently can report Allow with evaluation errors. Existing attach command owner does not bump the identity policy_versions guard, and a missing lock_policy_version row locks nothing.
NP1 enrollment uses real Cedar enforcement for server-derived registered object/action/property requests. Do not use generate_policies(Role) as its permission source, require a legacy role permission in addition to its own allow, or treat /policy/authorize client SimRequest as trusted runtime evidence. Protect enrollment by Company + object/data scope + operation family, including old reads of the same protected objects. Every legacy detail/list/aggregate/history/export/action alias reaching an enrolled resource must use its new authorization/projection or refuse; labeling only the new route enrolled cannot leave the old route as an escape. Preserve non-enrolled compatibility only for independently isolated non-enrolled data behind server-owned operation enrollment; an enrolled request cannot select LegacyOnly or downgrade after denial. Reuse compile_bundle_from_sources with the new closed typed schema/clauses. Any syntax/schema/entity/request/evaluation/panic/bundle-completeness error is a typed denied/unavailable outcome even when another policy returns Allow. Inspect diagnostics BEFORE returning Allow in both point and projection paths.

PA1.2 Physical bundle/assignment extension and correlation
Reuse identity-owned policy_roles as customer-defined capability bundle roots. Add immutable policy_role_revisions and typed policy_capability_clauses; existing permission/condition rows remain explicitly legacy projections. Clause binds exact registered action revision, resource kind/selector, field-group/property selection and bounded typed conditions. No wildcard includes future actions/properties automatically. Labels are customer vocabulary only; no seeded HR/executive/site-manager or seniority inheritance. Group reusable authoring templates can later publish explicitly referenced Company revisions; first enforcement stores each target Company's admitted bundle revision and provenance, never copies provider Company permissions by name.
Extend user_role_assignments into assignment roots with immutable policy_assignment_revisions and current head; preserve UUID/user_id naming as compatibility, retarget to CompanyActor. New revision holds Account, exact bundle revision, target Company, typed scope ref/descendants, field narrowing, [valid_from,valid_until), purpose/relied-on relationship refs, issuer/approved delegation ceiling and revocation state. Optional governed subject-group expansion is represented by its owner-verified membership revision; first enrolled assignments can be Account-bound without hardcoding job groups. Subject-group grants remain unavailable until its membership writer participates in the same authority guard.
Existing UNIQUE(org_id,user_id,role_id) prevents reusing a bundle for two independently bounded scopes. Replace it only after old replace-all writers/readers are upgraded or refuse enrolled assignments; new root IDs permit two scopes, and each is a full tuple. Reusable clauses and assignments intersect on scope/fields/validity/ceiling. Alternative complete assignments can permit the same exact request; never separately union all actions, scopes and field sets and take their cross product. Field edit permission is evaluated for the actual business action+target+property in the same qualifying tuple. Granting read on one scope and approve on another cannot synthesize approve/read evidence elsewhere.
Use versioned ont_object_type_key_revisions/action/property metadata as typed schema refs; additional action-version registration required by NP1 remains W04b-02. Field groups are governed exact schema-property membership revisions, not display-label regexes. Typed scopes reference existing Company/OrgUnit/task/resource IDs and explicit descendant rules from participating owners. A missing scope/field schema or unregistered owner action is a publish blocker, never arbitrary string matching. Identity persists bundle/assignment revisions; Cedar store/ont_policy_api remains sole catalog/attachment SQL writer. Borrowed-connection publication coordinates them; no second catalog writer.

PA1.3 Policy requests and forbids
Runtime request types distinguish EntityDiscover, PropertyRead, PropertyWrite(for business action), DomainAction, HistoryRead, ReceiptRead, QueryField(filter/sort/search/group), and DerivedRead. Registered action IDs are stable technical identities; they are not roles. Resource carries trusted Company/object/schema revision, actual containment/ownership/classification and current scope membership facts. Context includes trusted Account/session, evaluation instant, declared-and-validated purpose, exact task/attempt/evidence where needed. Raw caller subject/resource attributes never override owner facts.
Cedar generation emits predicates from each complete assignment/clause; scope membership and property permission occur inside that same rule. All applicable explicit forbids and immutable platform isolation/SoD constraints participate in the complete policy set. An alternate bundle or selected context cannot hide a forbid. Narrow exceptions are expressed in the reviewed forbid condition with exact purpose/assurance/validity/approval evidence, not a precedence toggle. Tenant policy author cannot change a higher-authority constraint or expand beyond delegated administrative ceiling. Publishing/revoking permissions, classifying protected fields and editing ceilings are independently authorized effects with exact expected revisions and required decision evidence; own review is not inferred from possession of an admin title.
Typed no-code grammar initially supports registered scalar comparisons, set membership, relationship/descendant selectors and bounded All/Any/Not over registered operands. Compiler validates types, finite input bounds and delegation scope. Unsupported predicates block publication for an enrolled required list surface rather than becoming ignored metadata. LLM interpretation and string similarity are not runtime policy dependencies. Arbitrary future Cedar programs are not silently admitted as SQL-translatable policies.

PA1.4 Authority guard and lock order
Choose company_authority_guards(org_id PK,epoch positive BIGINT) separately from legacy policy_versions: authority freshness includes hierarchy/ownership/classification facts and is not just a policy bundle version. Identity's authority-fact guard helper owns its monotonic updates; existing fact writers stay their sole domain owners. Initialize every enrolled Company's row before activation. Missing row => authority_unavailable/enrollment failure, never default0 or lazily inserted during a read. Group identity/topology uses group_authority_guards initialized with Group; Account security uses account_security and session family guards. schema-candidate fixes rows/permissions; writer-enrollment.csv names the minimum source writers.
Current read/progression obtains Group SHARE where required, sorted Account security/session SHARE, then sorted target/provider company_authority_guards SHARE; collect current fact versions, then follow TX1 work/parent/attempt/domain/governance order. Auth-only operations use their subset without a Company. Policy-relevant changes acquire corresponding Company guard EXCLUSIVE BEFORE modifying the fact, increment epoch in the SAME owner transaction as revision/head/audit/receipt. Group topology or human-proof mutations acquire Group guard EXCLUSIVE first. Domain/work writers whose changes affect authorization participate at their earlier guard, not only later business locks. No lock upgrades after domain/task locks; mutation knows its write lock need up front.
Covered changes include bundle/assignment publish/revoke/expiry-bound edits; Cedar object/property attachment/retire/detach/rollback; subject-group membership; Company membership/provider relationship; OrgUnit/scope/containment changes; field schema/group changes; resource ownership/confidentiality and any registered authorization-dependent attribute; workflow assignment/custody when referenced by policy. Pure unrelated payroll value changes need only their source guard unless that exact field is registered as a policy operand. A field cannot become a policy operand until all its writers are enrolled. Existing attach definer must call the guard before catalog mutation; assigning catalog policy_version=1 is not a current epoch.
One coarse Company guard is intentional: concurrent ordinary reads/effects use compatible SHARE, while authority changes serialize. No per-field lock table or distributed invalidation service before measured contention. Groups/Companies remain distinct cells; helpers return minimal proof, never salary rows from another Company. Source/writer closure is checked before each surface is enrolled; complete source business freshness beyond registered policy facts remains W04b-03.
Time expiry has no writer. Evaluate half-open bounds using authoritative clock_timestamp at the final authorization point, not transaction-start now() or browser time. Recheck shortest validity/session/assurance expiry immediately before protected effects/DTO release; expiry during calculation rolls back the new effect. Record authorized_at and minimum validity bound. Lock serialization defines whether a concurrent revocation or authorized snapshot wins; it does not recall legitimately released bytes. Cache compiled bundles only by exact schema/Company/action scope/policy-fact epoch and digest; subject-specialized compilation additionally keys Account and complete correlated-assignment digest, never reuses one Account bundle for another. Do not cache allow verdicts in this first slice. A rollback to an older policy payload is a NEW current revision/epoch and preserves independent current revocations; never decrement epoch or revive old grants.
Receipt reconciliation follows TX1: on optimistic miss collect/fence current facts without prematurely enforcing new-effect permission or current assignment eligibility, authoritatively recheck receipt at the command fence, then return current-disclosure-filtered historical success or authorize a new effect after proven absence. Guard deletion never strands receipt history; retained anchors/guards persist through Company archive and the narrow historical helper resolves exact historical control bindings.

PA1.5 One owner projection before serialization
Introduce an AuthorizedObjectProjection contract assembled by the owning use case under the shared Company authority snapshot, reused by detail/list/history/task cards/SSR. Object identity/title/type/relationship existence require discovery disclosure. Allowed property values only are inserted into the output map. Field keys/restricted markers appear only when field existence itself is authorized; no secret-field count, redaction manifest, null placeholder or debug/raw attribute bag. Missing optional fields are omitted, not business-null. Request mutation rejects supplied unauthorized fields and treats omitted fields as unchanged; it never round-trips redacted entities into full replacement writes.
Required human decision evidence is an owner/schema-defined set. All of it must be visible or satisfied by an explicitly approved sufficient attestation; otherwise the decision action is unavailable with an authorized repair route. Operational prepare/calculate can use hidden inputs only where the owning action explicitly permits that operation without human review of the inputs. It cannot pretend the caller approved hidden wages. Internal completeness/required-population proof is separate from what the initiator may see.
Relationship edge and target projections are both checked where applicable. History/diff/audit/receipt use current property disclosure, not only current-head row visibility. New grants never rewrite old actor identity. The same filtering precedes HTML, data-*, hydration, JSON, errors, ARIA labels, link titles, notifications and eventual subscriptions. Sensitive responses private/no-store; no CDN/shared rendered-object cache. Build and authorize the bounded DTO under locks, release the DB transaction before network streaming; no optimistic protected SSR chunk before projection authorization. Revalidation clears managed client caches, but already-disclosed bytes cannot be recalled.

PA1.6 Bounded query and derived information
Reuse restricted residual compilation, producing Cedar and SQL predicates from the SAME admitted typed capability definition and complete forbid set. No general Cedar-to-SQL optimizer. New list endpoints require an exact certified residual plan plus Company RLS. Apply authorization predicates before keyset pagination, then final per-object Cedar/field projection under the same snapshot. Page default25,max100; order uses public authorized stable key(s)+object UUID, never hidden salary/medical ordering. Query filter/sort/search/group fields each need the corresponding current permission; declared schema membership alone is insufficient. Bind parameters, escape no caller SQL/identifier, permit only registered query operations.
For Company-scoped object queries only, cursor is opaque authenticated data bound to Account, Company, query/selected scope, policy-fact epoch, schema/plan version, authorized last key and expiry. Cursor bodies/decoded hidden IDs never appear to the client or logs. For first slice use a server-owned random cursor handle with narrow stored continuation state and5minute TTL; no token signing/encryption scheme is invented here. Current authorization is checked again and epoch change gives stale_cursor requiring restart; no reuse across Company/Account. The cursor is continuation, not bearer read authority. This Company-owned cursor cannot serve Account-only context discovery; that separate owner/API contract remains a blocking W04b-04 dependency in boundary-api.json.
Fetch at most page_size+1 distinct object identities AFTER the exact authorized predicate; relationship/descendant/assignment predicates use EXISTS/semijoins or equivalent exact identity deduplication BEFORE LIMIT so multiple membership paths cannot duplicate objects or invent has_more. has_more/counts concern this permitted result only. The lookahead object is disclosure evidence even though its DTO is not returned: apply the same final Cedar discovery, query permission and current validity checks to it, and include its relied-on expiry in the final release bound. Never derive has_more from an unvalidated or dropped lookahead. If per-object Cedar disagrees with an allegedly exact residual, fail that response as projection_plan_invalid, emit a sanitized operator event and disable the affected plan until repaired. Do not silently drop rows after LIMIT and publish a misleading count. A malformed/untranslatable relevant forbid cannot be excluded to make a plan fast. If no exact plan exists, list is unavailable and a permitted known-object/task lookup may remain; do not fallback to fetch_all or expose repeated scan-empty cursors whose length reveals hidden population. Required workflow list support must be validated at policy publish so ordinary authoring cannot silently break enrolled work.
Derived totals/counts/groupings require explicit DerivedRead and query-field/dependency disclosure. Full aggregate is absent when it would reconstruct protected inputs, unless a separately reviewed owner safe-release contract authorizes that exact summary. First slice permits only explicitly authorized-subset aggregates with all relevant input disclosure, labeled as subset only if that distinction is disclosable; no generic k-threshold or arbitrary salary totals. Ordinary list has_more over exactly discoverable rows is its declared limited derived contract; it is not payroll amount access. No raw underlying salary is serialized as a checksum, error detail or sorting key.

PA1.7 Initial cost bounds and publication proof
Policy authoring limits are explicit candidate schema bounds, not resource measurements: max128clauses/bundle revision, max256active assignment roots/Account/Company, condition AST depth8 and128nodes/clause, input body64KiB; excess is a publish/assignment rejection, never truncation of live grants/forbids. Complete effective policy sets must also fit the separately configured compiled-bundle budget before enrollment; no runtime omission to satisfy a cap. This last byte/time budget and Company-scale contention measurements remain W04b-05. Query cursor creation reuses authenticated request rate limits and capped stored state; exact service limits belong to that same harness. Numeric limits are versioned protocol choices and change only with compatibility review.
