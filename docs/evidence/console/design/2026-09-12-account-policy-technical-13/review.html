설계 증거 · W04b-01 · 제품 구현 아님

계정은 계속 유지하고, 권한은 업무에 맞춰 확인

계정 보안과 법인 업무 관계를 분리하고, 동일 객체의 필요한 정보만 보여주는 공통 경계를 구체화했습니다. 최종 범위별 상태는 후속 독립 검토 영수증을 확인하세요.

사용자에게 생기는 차이

  • 지원 전·재직 중·퇴사 후에도 같은 계정으로 본인에게 허용된 업무와 기록에 접근합니다.
  • 회사 관리자가 업무를 종료해도 개인 패스키를 삭제하거나 로그인 수단을 가져갈 수 없습니다.
  • 직급·직책 없이도 회사마다 필요한 권한 묶음을 만들고 대상·필드·기간을 지정합니다.
  • 사람 카드가 보여도 급여·의료 정보까지 자동으로 보이지 않습니다. 과거 이력과 검색·합계에도 같은 경계가 적용됩니다.
  • 목록과 상세 화면은 같은 허용 데이터로 구성됩니다. 지원하지 못하는 정책을 무시해서 화면을 보여주지 않습니다.

기술 선택과 근거

기존 ES256·패스키·세션 갱신·Cedar 컴파일러를 재사용합니다. 계정 세션과 법인 업무 컨텍스트를 분리하고, 권한 변경과 실제 실행을 DB 잠금으로 순서화합니다. 평가 오류가 있으면 다른 permit이 있어도 보호된 결과를 제공하지 않습니다.

  • 계정·세션·인증수단·퇴사·복구
  • 상관된 권한 묶음·필드·조회·잠금
  • 18개 테이블의 제안 키·제약·접근 경계
  • 11개 API 경계·탐색 API 미완료 조건
  • 확인한22개 변경 경로
  • 정상·공격·경합29개 비실행 검증 후보
  • 마이그레이션·호환·남은 준비

법인 선택 전의 접근 가능한 업무 목록·페이지 탐색 계약, 정확한 적용 DDL·권한 catalog·공통 action/draft/attempt 등록·source/업무 엔진 참여·실행 테스트는 아직 남아 있습니다. 계정 기반을 설계했다고 지원·증명서·외부업체 업무가 구현된 것은 아닙니다.
