수정 설계29 — 승인 요청
설계 SHA: e249e0a537d1246d770904a24326a75a61974418
상태: 독립 검토4명 모두 같은 SHA를 수용했습니다. 사용자 설계 SHA 승인은 별도이며 아직 받지 않았습니다. 이전28과 추가 반대 검토 기록은 그대로 보존합니다.

원문과 반례를 대조한 뒤 동의한 공백만 수정했습니다.
1. 문의·답변은 typed 내용 입력을 받고 제출/응답 액션이 공용 revision을 같은 트랜잭션에서 생성합니다. 사용자가 먼저 내용 객체를 만들 필요가 없습니다.
2. 반복 항목의 읽기·수정·오류가 FieldAddress를 공유합니다. 미완성 숫자도 해당 항목 ID와 함께 보존됩니다.
3. 이력 저장 시각을 별도 권한에 따라 생략하면서 허용된 이력 자체는 제공합니다.
4. 선택적 예상 수량/금액/단위와 정확한 과거 공개 항목 연결을 복원했습니다. 사용자의 주장이 자동으로 급여 사실이나 승인 권한이 되지는 않습니다.
5. 실험용 DB 연결 배분을60개로 일치시켰습니다. 실제 부하·복구 성능은 아직 측정하지 않았습니다.
6. 일반 검토 결재의 저장 근거와 실행 게이트의 봉인된 명령 연결을 목적별로 바로잡았습니다. 입력 폼의 편집 토큰은 결재 근거로 저장하지 않습니다.

초안 버전ID 누출이 불가피하다는 가설과82GiB 단순 비교에 의한 불가능 주장은 반박 검토에서 제외했습니다. 관측된 보안 사고나 성능 실패를 수정했다고 주장하지 않습니다.

범위는 공용 객체/권한/초안/결재/인계/보존·운영·복구와 첫 비지급 급여 검토 흐름입니다. Account는 퇴직 후에도 유지됩니다. 전체 Foundry suite, 전체 HR 상세 업무, 증명서/채용/외부업체/연락도구/시트 완료를 뜻하지 않습니다. 이전 설계의 명시적 후속 요구와 production/지급/법적 판단 HOLD는 유지됩니다.

정적 검증과 독립 검토를 수행했습니다. 제품·SQL·Verus·부하 실행은0입니다. 현재 authority 변경도 없습니다. 승인 후 제안된 현행 권한 문서 반영 후보/필수 게이트, 실행 가능한 테스트 후보 작성·독립 검토, 정확한 테스트 SHA 승인, 실제 RED와 fanout 구현 진입 순서로 진행합니다.

현행 docs/current/DELIVERY.md는 “Four independent design-review rounds, consensus, and a revision-bound explicit approval (design SHA).”를 요구합니다. 이 문서는 위 정확한 설계 SHA에 대한 승인 대상이며 테스트·구현·배포 승인을 대신하지 않습니다.
