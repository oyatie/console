SG1.1 Existing owners
Payroll SQL stays in payroll/adapter-postgres; arithmetic remains payroll/domain. Wage source_note and import VERIFIED_SOURCE_ROW are narrative/legacy labels, never new authority. Actual self-clock/material INSERTs live in backend/app/src/hr.rs, not the attendance adapter. Consolidate those statements into the responsible attendance adapter in the implementation candidate, with the old app route delegating; do not leave two writers. Canonical Employment owns Employment/employee/source bindings; leave owns leave requests and charge decisions. Docs owns evidence object/copy/custody/pins; platform/storage owns byte transport and trusted version verification. WorkCalendarPort already exists in leave/application; its ManualReferenceCalendar production default reports missing calendar/policy. Implement its calendar source through the attendance owner and wire it through app, not through a communications calendar or a parallel leave calendar.

SG1.2 Smallest safe source guard
Add source_family_guards(org_id,family,generation) in platform/db's existing transaction/period-guard responsibility. Closed families: POPULATION,EMPLOYMENT,WAGE,ATTENDANCE,CALENDAR,LEAVE,ELIGIBILITY,TAX_EVIDENCE,QUALIFICATION,ARTIFACT. Rows are initialized for every enrolled Company/family before traffic; missing is unavailable, not generation0 or lazy insertion while reading. Family is a registered type, not caller text. Source writers retain their own SQL but acquire their declared family EXCLUSIVE and increment generation in the same commit as their fact/audit/receipt. Source readers SHARE the needed rows and perform exact predicates including absence. This deliberately coarse first proof catches insertions and newly competing facts; it does not claim fine-grained contention.
Reuse TX1/DA1 early Group/Account/Company-authority/work/attempt/command ordering. Refine class9 consistently across enrolled source writers and payroll commands: existing period-lock keys first, then sorted (Company,family) source guards, then domain run/source heads in registered order. All participants declare their write families up front; no SHARE->EXCLUSIVE upgrade. Prepare/close that writes assessment/coverage metadata takes the needed EXCLUSIVE family at entry. A writer whose fact is a Cedar operand also takes the earlier Company authority EXCLUSIVE before any source/domain fact. Existing Employment and self-clock period checks need the real lock_period_lock_key fence, not only assert_period_open lookup; close/amendment/writers use the same keys before effects. Cross-owner composition borrows one connection, no network I/O under these locks.
Every related writer is enrolled or refuses enrolled data. POPULATION covers employee creation/deletion/current scope mapping, Employment associations and hierarchy/assignment facts used in scope selection. Home-branch/current text cannot silently substitute for a versioned historical Company/OrgUnit selector. Existing direct SQL, app aliases, imports, migrations and maintenance are part of closure; a source operand cannot activate with an unenrolled writer. Exact catalog/ACL proof remains W04b-05.

SG1.3 Epoch is a concurrency witness, not business meaning
Store captured family generations with the immutable manifest. On changed generation, automatically re-resolve the complete relevant predicate under current guards and compare exact source refs, temporal coverage, chosen set and typed absence/selection digest. An unrelated worker's new clock event may increment ATTENDANCE without changing this unit; that does not force human correction or invalidate unaffected PC1 approval. Original input revisions remain immutable; a current revalidation witness records observed generation and SAME_BASIS or CHANGED_BASIS separately. No verdict cache survives an unfenced source change.
A different relied-on source revision, newly competing Employment, changed membership/day disposition, replacement artifact/qualification, even an equal-value wage on a new effective date, changes semantic basis. Reprepare/review/correct through accepted NP1/PC1/AC1; do not mutate old manifests or replace historical successful receipts with stale_source. Whole selected population includes hidden/blocked slots. Its completeness proof is server-owned; a visible employee list cannot become source authority.
Coarse family locks can delay self-clock writes during calculation. That is a material operational risk, not an accepted latency promise. W04b-05 must measure clock-save tail latency, waiters, calculation transaction time and WAL for the six-Company/2000-person pilot. Enrollment stops if budgets cannot be met; then refine to proven subject/period scopes or shorten locked computation in a reviewed change. Never drop a clock event, bypass the fence or silently treat a timeout as success to make a benchmark pass.

SG1.4 Global rules and time
payroll_statutory_rates is a global migration-owned citation register with runtime SELECT only. Company guards cannot protect its deploy changes. Pin a reviewed immutable rule-bundle ID, kernel/source build SHA and exact citation-row digest set in profile/input. No runtime editing of statutory rates or tenant-supplied percentage. Before publishing a new executable bundle, pause affected admissions, drain old executions, install compatible readers/code/catalog and atomically select the reviewed bundle; sealed old input is executable only if explicitly still supported. No mixed new-rate/old-kernel calculation. Exact deploy/rollback rehearsal is W04b-05, and legal qualification is separate authority.
All reads capture one authoritative UTC microsecond instant through a clock port supplied by the owning transaction/harness; final effect/disclosure expiry rechecks use the authoritative current clock. Dates use Asia/Seoul earning calendar, not browser/server zone. Production clock comes from database/runtime authority; deterministic synthetic clock comes only from isolated test composition. No request flag, tenant setting or user role selects fixture clock/source mode.
