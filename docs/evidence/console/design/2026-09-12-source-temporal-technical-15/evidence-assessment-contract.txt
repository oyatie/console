EA1 — Exact artifact custody and purpose-specific source qualification

EA1.1 Preserve originals and reuse owners
Reuse PgDocsStore/docs_evidence_objects/docs_evidence_copies and platform/storage. Existing upload is WorkOrder-bound and may transcode media. Add a typed payroll-source upload subject through the existing Docs/storage owners, no fake WorkOrder or employee task. Original bytes remain original; normalized text/table/rendered PDF is a derivative with exact parent/version/transform identity. Initial supported original inputs are bounded PDF or UTF8 CSV for this source path; unsupported HWP/other formats require a reviewed derivative+original custody path, not MIME relabeling. Original PDF is not rendered inline as executable content; viewer/download policy and scanner state stay separate from source qualification.
The browser receives an authorized upload ticket for server-owned key/size/type/expiry; it never chooses provider credentials/bucket. After upload, a trusted storage verifier reads the exact immutable provider version, hashes the actual bytes and records size/content type/version. Extend storage's generic trait with version-addressed read/head/retention and conditional immutable copy when needed; no latest-key fallback, ETag-as-SHA assumption or success when checksums are absent. Verify configured retention deadline/mode when required, not merely non-null timestamp. Network verification occurs outside payroll transactions and returns a durable docs-owned attestation. Final admission locks its current state, rechecks exact tuple, expiry/revocation/quarantine and pins it in the same transaction as qualification/evidence creation.
ArtifactRef on the wire contains Company,evidence_object_id,copy_id,attestation_id,attestation_revision. Provider/bucket/key/version/actual SHA256/size and parent/source relationship are server-owned immutable attestation data. Uploaded checksum/confirmed_at/legacy VERIFIED cannot replace them. Migration0195 currently does not bind provider/bucket/version and evidence confirmation merely stamps a row; these are source facts requiring stricter enrollment. No raw storage key, presigned bearer URL or unqualified source label is a payroll source identity. Current byte retrieval uses Docs authorization proxy with exact version; no public presigned source URL that bypasses revocation. Already lawfully downloaded bytes cannot be recalled.

EA1.2 Qualification is an object, not a label
payroll_source_qualification_revisions plus current heads are payroll-owned purpose-specific admission/verification/revocation. They reference a Docs original/derivative set and qualified-review artifact, edition identifier, source kind (TAX_TABLE,APPLICABILITY_RULE,WORK_CALENDAR_RULE,RULE_BUNDLE,REVIEWER_CREDENTIAL), exact allowed parser/normalization method and finite date applicability. Responsible professional-review credential/evidence is itself a verified current owner ref with issuer/scope/validity; job title or Company admin is not qualification. A declared source_url is citation metadata, not custody/authenticity proof.
Propose stores immutable content; independent verify binds exact digest and current evidence under AI1 distinct-natural-person requirements. Verification and later revocation append revisions/CAS head; original source bytes and historical calculations remain. Self-qualification, tenant uploaded verified=true, revoked/expired evidence and an unknown verifier qualification are refused. Group-shared review evidence can be reused only through an authorized Docs share/admission into the target Company, preserving original provenance; no Company foreign-ref/RLS bypass or duplicated human title grants.
These records establish the product's technical use eligibility. They do not establish Korean legal compliance or authorize payment/production. Qualified legal conclusions and statutory-source/kernel changes require separate authority. Runtime cannot edit global statutory percentages through this object.

EA1.3 Exact tax evidence and selection
Initial normalized TaxSelection is taxable_monthly_won,dependent_count_including_self,eligible_child_count,withholding_option(P80|P100|P120),selection_fact_refs and income_definition_ref. Counts are protocol-bounded integers, not an assertion all counts/options are supported by a source. The qualified edition's schema states supported combinations and tax basis; unsupported or missing facts blocks selection. Actual subject/family/withholding facts come from current independently assessed sources, not values inferred from notes. Selection binds Company/employee/EmploymentCoverageRef/period/pay_date; tax basis must equal the selected eligibility assessment, not assumed gross by name.
TaxRowLocator is either PDF_TABLE_CELL{page,table,row,column,locator_schema_ref} or CSV_RECORD{record_ordinal,column_name,locator_schema_ref}; indices are1-based bounded integers and column name is from the source schema. CSV uses RFC4180 UTF8 with explicitly declared header/delimiter policy, no spreadsheet formula execution; PDF table IDs refer to a reviewed locator map. A qualifier also records every relevant note/footnote/rule locator. Matching an income band alone cannot omit a child adjustment or table note. Income band has lower_inclusive_won and upper_exclusive_won or explicit unbounded upper; source units are declared and converted by the registered exact integer codec. Overlap, gap, unknown units or a changed edition is not a guessed match.
Tax evidence admission stores typed selection, exact assessment and artifact/qualification refs, locators/rule refs, table edition, exact final income/local tax amounts and digest. A separate authorized verifier, a different verified human from admission, reviews the exact complete binding and appends verification. Supersession admits a new record; revocation appends state, never edits old amounts. Native construction of VerifiedNtsTaxRow is reachable only from this verified owner result. Legacy VERIFIED_SOURCE_ROW and imported free JSON remain legacy lineage, not qualification.
Candidate12's deliberate independent verification remains required. Automate fact resolution, row matching, diff grouping and preparation of review candidates when an exact qualified normalizer exists; no repeated free-text explanation per employee. A bounded review command may cover an explicitly selected digest manifest only when every covered evidence item is independently eligible and visible; it cannot silently approve hidden or changed items. Until a qualified edition/normalizer has reproducible source equivalence proof, manual located-row admission is the supported recovery path and its operational cost remains visible. This packet does not claim an automatic NTS parser exists or that a human must retype2000tax amounts every month. The first production normalizer/qualified dataset is an explicit unresolved source-supply prerequisite; fabricated positive fixtures cannot clear it.

EA1.4 Eligibility assessment is separate from tax and close
payroll_eligibility_assessment_revisions plus heads reference exact EmploymentCoverage, WageFact, WorkCalendar/attendance coverage, resolved leave/exception dispositions, profile/rule bundle, insurance applicability for each deduction, explicit pension standard income and taxable-income definition/value. Typed insurance status is APPLIES|NOT_APPLICABLE|UNKNOWN with qualified reason/source; NP1 accepts only the exact configuration supported by its kernel profile. UNKNOWN is not false; pension basis never defaults silently to gross. Assessment also records all covered obligation families and no-adjustment result from their complete sources. Missing family, uncertain breaks/premiums, pending leave or competing source blocks the unit.
Propose uses current owner facts and schema-defined manual inputs only where a required source cannot be automatically derived; independent verify binds the exact assessment revision and qualification. A checkbox alone cannot certify no overtime or insurance status. Assessment verifies non-tax eligibility/taxable basis; it does NOT require the later tax evidence it will generate, nor a later payroll run close. Then tax evidence binds the verified assessment; preparation binds both; run close binds complete current coverage and operational close. There is no assessment<->tax or assessment<->run-close dependency cycle.
Assessment correction/revocation is append-only. Different source revision changes basis even if displayed value matches, unless a separately reviewed owner equivalence contract explicitly permits it. Missing/blocked assessment still produces a required PopulationSlot with actionable owner repair; hidden slots remain in completeness. Successful historical execution is always reconciled before new-effect source checks, perTX1/DA1.

EA1.5 Pins, expiry and retention
Docs/payload pin creation, qualification/assessment/tax admission, verification/revocation and disposal share ARTIFACT/QUALIFICATION/ELIGIBILITY/TAX_EVIDENCE guards plus their own current heads in fixed order. Source and domain retention pins are distinct from private draft pins. A draft pin released after domain adoption does not release the domain's source retention requirement. All generic Docs disposal and storage cleanup aliases respect those pins and current holds; dispose_object's current legal-hold-only check is insufficient. RR1 independent journal/restore admission remains required where physical deletion can affect retained proofs. Do not claim migration0201's no-op implemented it.
Temporal expiry is evaluated using current clock at final use. Revocation blocks new prepare/verify/close/calculate/review use but never mutates prior receipts. Integrity loss/quarantine means unavailable current evidence and a repair route; it cannot be overwritten with a newly recomputed matching hash. Exact retention periods, trusted verifier ACL/provider conformance and recovered current authority are W04b-05/production obligations.

EA1.6 Server selection, ambiguity and explicit successor activation
Per-root heads alone are not a selector. For each server-derived required PopulationSlot, resolve exact Company, employee/Person, Employment identity+binding+ordered coverage segments, earning period, pay_date and profile/rule-bundle revision. Eligibility candidates must match that tuple and the currently resolved wage/calendar/attendance/leave/insurance/taxable-definition source basis. Tax candidates must additionally match the exact selected verified assessment revision, normalized TaxSelection, qualified table edition/applicability/locator rules and attested artifact. Qualification candidates match their required purpose, exact source edition/artifact, date and normalization rule; no latest-created/UUID tie-break. Every candidate must have a current active VERIFIED head, current bounded dependency closure and compatible exact source refs. Enumerate all matching roots under their source guards, including hidden candidates: zero is MISSING_SOURCE, one is selected, more than one is AMBIGUOUS_SOURCE even when amounts/digests happen to agree. Discovery of hidden ambiguity blocks completeness without exposing hidden refs/counts. Limits use a refusal sentinel, never truncate to one.
Correction/supersession names an exact predecessor root+head revision and compatible same subject/obligation/purpose lineage, stored in the immutable new PROPOSE payload. ADMIT_TAX has required-nullable supersedes_ref:TaxEvidenceRef|null; source qualification and eligibility proposals analogously have SourceQualificationRef|null and EligibilityRef|null. Null is ordinary admission, never an inferred replacement. It is not an implicit latest-wins link. A proposed, rejected, expired or revoked successor does not deactivate its predecessor. Predecessor validation checks identity, lineage and exact head CAS, NOT continued validity of the predecessor's old source basis: replacing a now-invalid wage/tax source is a legitimate correction.
VERIFY locks all declared families and sorted heads, verifies the new candidate against current sources and checks predecessor head revision plus activated_successor_ref IS NULL. For a predecessor whose head is VERIFIED (whether or not its underlying old basis remains usable), append predecessor SUPERSEDE naming the new exact verified successor and advance both heads atomically. For an already REVOKED predecessor that was previously verified, leave its terminal history/head revision REVOKED; atomically claim its initially-null activated_successor_ref in the owner head projection and activate the new verified root. This recovery linkage never changes a terminal REVOKE into SUPERSEDE or VERIFIED. In both paths store the same exact successor ref on the predecessor projection in the same transaction; this one-successor CAS prevents two simultaneous activations. A SUPERSEDED predecessor or any already-claimed predecessor cannot acquire another direct successor; a further recovery must explicitly address the later lineage head, not silently skip it. PROPOSE-only roots cannot be used as verified replacement predecessors. Revocation remains terminal for an admission, while immutable lineage recovery records describe a different admission.
Changed basis may be legitimate correction within the same lineage and must be reviewed explicitly; a different subject/purpose cannot supersede it. Competing successor verification permits at most one predecessor revision+empty-successor CAS; the loser replans and cannot retire an unrelated head. Ordinary admissions without a supersedes claim may coexist but then the exact selector returns ambiguity and requires an authorized explicit resolution. SUPERSEDE and REVOKE never resurrect their admission. Revocation of a successor does not automatically resurrect a superseded predecessor; recovery needs a new verified admission with preserved lineage. Proposals are never silently treated as current sources. This rule applies to qualification, credential, assessment and tax admission roots. Historical manifest and receipt refs continue to name their original revisions.

EA1.7 Professional reviewer authority without circular self-qualification
Reuse payroll_source_qualification_revisions/heads with the distinct REVIEWER_CREDENTIAL payload in wire-types.json; do not invent another credential writer. It binds exact natural-person subject, issuer credential identifier, profession, jurisdiction and finite purpose/scope/date applicability, issuer verification evidence and a pinned IssuerTrustProfileRef. Verified account-to-human identity from AI1 proves who the person is; it is never proof of this credential. Source verification resolves a current ProfessionalCredentialRef for the actual verifier and matches its declared purpose/Company/scope/validity to this exact action.
Credential authenticity VERIFY terminates at an externally grounded issuer trust profile: a deployment-owned immutable reviewed register of allowed issuer IDs, professions/jurisdictions, verification methods (SIGNED_ISSUER_RESPONSE or INDEPENDENT_ISSUER_CHECK), independent operator requirements and exact root evidence. The issuer response/check evidence is attested Docs material. An independently Cedar-authorized, identity-verified human operator may admit issuer authenticity under that pinned profile without possessing the credential being checked; proposer and verifier must be different natural persons. This permission proves only issuer authenticity, and cannot turn that operator into a professional reviewer. No tenant-admin flag, user-supplied credential, self-signed response or source qualification can bootstrap the trust root. Actual issuer grounding/operator enrollment and verified root artifacts are unresolved source-supply/ACL prerequisites, not claimed existing infrastructure.
For every new downstream verification/preparation/close/calculation/review, resolve the current credential and issuer profile state as well as source/assessment/tax heads. A still-VERIFIED dependent row cannot bypass revoked, expired or superseded trust. Credential chains are closed and acyclic: source or applicability qualification -> reviewer credential -> issuer trust profile -> exact issuer evidence; REVIEWER_CREDENTIAL verification cannot depend on another professional credential. All reachable refs are enumerated with finite source manifests, max32 per reference list, no recursive arbitrary graph walk. Unknown/over-limit/missing trust blocks with an owner repair path. QUALIFICATION/ARTIFACT guards fence runtime credential/evidence changes; deployment-owned trust profiles use SG1.4 pause/drain/compatible bundle publication and current profile revocation checks. Pin profile revision+content hash and refuse unsupported/revoked profiles at new use. Revocation never edits historical calculations and historical disclosure still uses current Cedar. Revoked credential reinstatement requires a new independently verified superseding admission; no head reset to an old VERIFIED revision.
