제출 증거는 지키고,
불필요한 작성 이력은 안전하게 정리한다.

초안은 공통 객체 엔진의 객체입니다. 보존과 폐기도 그 소유자가 처리합니다. 계정 유지, 제출 당시 증거 보존, 작성 중 개인정보 폐기를 한 가지 수명으로 묶지 않습니다.

설계 후보 · 실제 삭제나 복구 작업 아님

두 독립 검토자가 취소 경합 수정 후 범위 내 수락했습니다. 검토 SHA: ab7efa258e37871ab75330c8daa9d0d192252cad. 전체 설계나 구현 승인은 아닙니다.

39개 시나리오와 13개 화면 상태는 실행 가능한 테스트가 아닙니다. 제품 코드·마이그레이션·배포 설정을 변경하지 않았고, 실제 데이터를 삭제하지 않았습니다.

무엇을 남기는가

자료보존 기준
개인 작성 중 수정·취소한 값초안 보존 정책. 제출 기록 접근 권한으로 자동 공개하지 않음.
제출 당시 확정 입력·필수 메모·첨부업무 소유자가 정확한 제출 snapshot을 인수하여 업무 기록 정책으로 보존.
진행·결과가 불명확한 제출결과를 확인할 때까지 입력과 pin을 유지. 만료만으로 삭제하지 않음.
법적 보존 등 별도 의무가 걸린 원본해당 의무가 해제되기 전 보존. 업무 담당자 직함으로 우회 불가.
초안 식별·명령 처리 결과필요한 최소 tombstone/영수증. 오래된 요청이 새 업무를 만들지 못하도록 유지.
로그인 Account초안 폐기의 대상이 아님. 채용 전·퇴사 후 접근 연속성과 구분.

제출 증거가 원본 초안에만 남아 있으면 원본을 지울 수 없습니다. “snapshot이 있다”는 이름만으로 보존 연결을 해제하지 않고 필수 내용의 실제 인수를 확인합니다.

사용자는 복잡한 폐기 절차를 수행하지 않는다

개인은 저장된 초안을 재개하거나 폐기 요청을 할 수 있습니다. 정해진 정책에 따른 정리는 자동으로 진행됩니다. 담당 업무는 동료가 부재하다는 이유로 만료시키지 않습니다. 실제 보존·재시도·복구 권한이 있는 사람에게만 그 화면을 보여줍니다. 아래 담당자 구분은 설명용 업무 맥락이며 고정된 역할이나 직급이 아닙니다.

상태보이는 내용
초안 종료초안 없음/만료 안내. 이미 제출한 신청이 철회된 것은 아님.
제출 증거 보존제출 당시 입력과 업무 결과 조회. 폐기된 개인 중간 이력은 없음.
정리 대기·진행보존 담당자에게 대상·근거·진행 상태. 일반 사용자에게 기술적 job/SQL 작업 요구 없음.
보존 의무 발생추가 삭제 중단. 이미 제거한 부분과 남은 부분을 정직하게 구분.
복구 결과 불명영향받은 자료 사용 제한. 근거를 가진 담당자의 조사·재시도 경로 제공.

삭제 완료를 세 가지로 구분한다

  1. 서비스에서 열람 불가: 삭제 준비부터 초안을 격리하여 오래된 탭·검색·이력 경로로 사용하지 못하게 합니다.
  2. 운영 DB에서 제거: 제한된 단위로 실제 제거하고, 제거한 범위와 영수증을 함께 확정합니다.
  3. 백업 등 사본의 상태: 남은 백업·WAL·파일 버전·복제본을 별도로 추적합니다. 운영 DB 삭제와 같은 완료 표시로 합치지 않습니다.

현재 배포 파일에는 35일 백업 보존 창이 설정되어 있습니다. 백업 의존성·보존 잠금·실패한 정리 작업 때문에 실제 복원 가능 기간은 다를 수 있습니다. “삭제 후 35일이면 완전 파기”라고 약속하지 않습니다.

백업 복구로 삭제된 자료가 돌아오지 않게 한다

삭제 전에는 독립된 보관 위치에 정확한 대상과 범위를 기록합니다. 실제 삭제된 범위의 결과도 이어서 기록합니다. 취소는 먼저 내부 실행을 막고, 외부 취소 기록을 확인한 뒤 완료합니다. 데이터베이스와 그 안의 원장을 함께 과거로 되돌려도 이 외부 기록은 남아야 합니다.

복구 시 발견한 증거처리
외부에 확정된 삭제 결과가 있음정확한 대상만 재적용. 과거 SQL 문자열이나 임의 조건식을 실행하지 않음.
삭제 의도만 있고 결과 불명해당 자료와 의존 화면을 격리. 영수증이 없다는 이유로 무효과/삭제 완료를 단정하지 않음.
정책·권한·업무 결과가 과거 상태현재 상태 확인/재수립 전 서비스 재개 금지. 옛 세션과 작업자의 실행 권한도 폐기.
검증한 자료·권한·처리 결과가 일치새 운영 세대로 허용 범위를 명시하여 서비스 재개.

기존 구조를 사용하고 필요한 경계만 보완한다

공통 revision store, 삭제 사실 원장 erasure_ledger, 외부 서명 검증, storage 소유 계층을 재사용합니다. 삭제 원장은 현재 기록과 감지까지만 제공하므로, 동일 transaction 참여·독립 보관·정확한 복구 재적용은 추가 계약이 필요합니다.

선택지판단
soft delete만 사용접근 종료에는 유용하지만 보존된 개인정보 제거를 해결하지 못함.
제한된 실제 삭제 + 독립 기록 + 복구 전 정리이번 기준안. 기존 PostgreSQL/객체 소유 구조에 맞고 사본 잔존을 명시적으로 다룸.
객체별 암호화 키 폐기백업 보존 창보다 빠른 비복원성이 필요할 때 재검토. 키 백업·권한·검색 비용과 별도 증명 필요.
별도 Git/초안 DB보존·복구 문제는 그대로이며 저장소를 늘리므로 선택하지 않음.

남은 구현·운영 증명

좁은 삭제 SQL/권한·trigger migration, 독립 보관 provider의 조건부 쓰기와 최신성·접근 분리, 실제 백업 inventory와 복구 훈련, 보존 기간의 적법성 검토는 아직 실행되지 않았습니다. 전체 설계와 테스트 SHA 승인, 운영·production 권한도 별개입니다.
