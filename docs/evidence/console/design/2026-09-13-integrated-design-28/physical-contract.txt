PH28 — Physical mapping and fixed enforcement
This is a proposed database/owner specification, not applied DDL. storage-mapping.json selects physical columns, registered typed content, identity and inherited constraints.13-16 definitions are inherited only where not normalized below;21/23 key/event projections and18/22/24/25 physical fragments take precedence over17's earlier inventory. No prototype bytes or relation names become authority by existing locally.

Common content and native control
Reuse accounts as global identity and separate native Account/Group controls. policy_capability_clauses becomes bounded PolicyRoleContent in an exact common revision referenced by native role revision. policy_scope_revisions and policy_field_group_revisions are registered Company object revisions; native assignment/role rows bind exact common tuple and keep indexed assignment/head/validity/field narrowing. ont_action_input_schema_revisions keeps native registry header but replaces definition JSON duplication with exact definition_revision tuple. Workflow waiting-task control is one-to-one native subtype because assignment epoch/capacity/receipt coupling must remain owner-confined. Existing governance requests/decisions/consumptions retain identities; native binding/control subtype supplies immutable purpose and exact basis. Publication controls retain the inherited one-to-one native control row, with separate unique lineage/subject current slot; content identity stays immutable. Account cursor and Company authorized query cursor remain separate.
Each exact common reference is physically six columns org_id,instance_id,revision_id,version,object_type_id,row_hash (shared org_id reused). A deferred native constraint checks matching actual ont_instance_revisions row and parent instance/type; immutable bind projections cannot be retargeted. All referenced non-disposable definition/evidence content is pinned until obligations release. Generic actor fields in Company rows physically remain account UUID plus existing org_id composite CompanyActor FK, not serialized CompanyActor JSON. Account/Group receipt refs remain tagged native identities with no sentinel Company. Immutable content may be JSONB with an admitted exact schema; native identity, uniqueness, exclusion and membership are never merely JSON array conventions.

Scalar and relational conventions
All required columns NOT NULL unless mapping explicitly nullable or a staged transition below requires null before publication. UUIDs nonnil; revisions/generations positive signed i64 with checked increment, no wrap/reset. Digests BYTEA length32. Date ranges half-open daterange with no empty/infinite bound for admitted finite business scopes; nullable exclusive end only where actual temporal contract allows ongoing employment. Timestamp precision microseconds. Decimal leave units preserve existing exact NUMERIC semantics; monetary values checked integral won, never float. Every enum has CHECK and closed owner mapping. Each typed JSONB column has max byte/depth/count checks and exact compiled schema decoding at the trusted owning executor; structural identity/projection/FK checks are independently enforced by native owner functions/triggers. A registered schema name is never a caller callback or a loose validated=true parameter.
Account FKs use accounts(id) ON DELETE RESTRICT and preserve historical nullable actors. Company actors use (org_id,account_id) in company_actors; no Employment-active prerequisite. Each Company child uses composite parent FK including org_id. Mutable head points to exact own revision and same parent/type via deferred FK/check; new-head initialization verifies unique open revision and exact parent atomically. Immutable revision body/discriminator/hash/identity cannot UPDATE/DELETE through runtime, with the sole named payload-removal owner preserving tombstone and current head consistency. The prior common head app-maintained comment is not enforcement; enrolled common instances require actual exact-head deferred constraints and guarded pointer mutation.

Source projection normalization
Seven source tables use21 actual primary keys and no unused generic id. Creating command+custody digest+effect ordinal bind22/23 reciprocal native REVISION membership. Source payload narrative/body resolves exact24/25 independently retained submission using that effect identity; do not store a self-referential SourceRevisionRef as substitute body or duplicate editable narrative JSON. Runtime loader follows source->effect->adoption->submitted snapshot, validates registered19 body and exact event kind, derives indexed projections and compares every stored projection before returning admitted source. Missing independently retained body is unavailable, not empty source. PROPOSE/VERIFY/REVOKE/SUPERSEDE event structure, predecessor original admission and immutable successor claim follow23 exactly. No event4, revived predecessor or one-command-one-source shortcut.
Four ordinary source families carry root/head CAS with no missing-row default: calendar, assignment, coverage and close basis. Head relation key (org_id,root_id), current_revision>0, current command/custody tuple matches exact latest owner revision; insert absence uses compiled creation key. Three qualification/eligibility/tax heads retain23 exact current_revision and nullable successor_claim_command_id; old activated_successor_ref is a derived projection. All head uniqueness/indexes include Company/root. Coverage includes Employment identity, period and outcome; close basis includes period/scope, operational_close_id plus complete amendment set/digest and actual period_lock_id; remove amendment_revision fiction. Qualification stores kind/purpose/admission digest; eligibility stores employee/Employment/period/admission; tax stores employee/period/admission/assessment-selection correlation. Every searchable scalar derives from decoded19 payload in same finalizer; forbidden contradictory duplicate representation fails.
Historical employment binding has binding_id,Company,employee,Employment,revision,from_us,to_us,state and exact canonical Employment revision/source-binding receipt. These facts need canonical owner correlation and overlapping interval exclusion; a self-reference JSON payload cannot prove it. Wage corrections reuse actual base wage row plus immutable correction revisions/head, exact previous revision and amount/kind/standard hours per18. Original base correction0 persists. Docs attestation identity uses attestation_id+revision, exact existing copy/object/provider binding/version, readback hash/size/MIME, verification receipt/state, observed/retention instants and owning audit/command. An arbitrary provider-step object is not an attestation.

Review cycles/members/bases/completion retain native exact Company/run/cycle/obligation keys. Basis->gov request one-to-one immutable linkage distinguishes REVIEW_DECISION from EXECUTION_GATE. Completion unique per cycle/run current basis and requires every current obligation covered by a current valid decision or exact retained unchanged decision dependency proof. Deferrable member/source/receipt constraints execute after all provisional participants and forbid late unsealed additions. Publication identity immutable subject/source/Completion/projection/content; slot UNIQUE(Company,subject,lineage,purpose), monotonic slot generation and exact current publication FK. Work and Group integrity
Group control keys never use Company runtime GUC. Group task charge key=(Group,targetCompany,task), assignment epoch/account/units/state plus current membership incarnation. used_units equals current ACTIVE charge sum; assignment transfer locks exact old/new routing accounts then task, changes charge and assignment plus append-only delta receipts once. UNKNOWN remains charged. Missing capacity/current availability yields no candidate, never infinite default. Group capacity changes can place account OVER_CAPACITY without silently removing tasks; disallow additional positive charge until current capacity allows. Work definition/coverage/plan content are exact common revisions; native target members<=20 persist immutable epoch expectation and TEMPORARY/PERMANENT. Each task transfer is atomic, whole plan need not be. Generic task DML cannot independently update assignee/epoch/charge.
Group operations have native Group/operation/slot identities, exact Company/incarnation/command/attempt link, original Account and session binding, control/dispatch epochs. Unique(Company,command) reservation remains Company-owned; Group receipt namespace separate. Child claiming is fixed authenticated workload principal ID+generation, not free text/role label. Stop takes parent exclusion and closes future claims; unknown old claim isn't cleared on timeout. Membership removal invalidates new positive admission but historical charge release remains possible through retained incarnation. Current topology requires append-only membership incarnation identity; created_at alone cannot serve it. Extend existing membership owner with incarnation row and exact join/leave receipt, never forge historical incarnation where evidence missing; legacy unknown blocks positive group dispatch until enrolled.

Privilege and deferred closure
Creation transaction revokes PUBLIC and default console_app/console_rt DML/EXECUTE, installs FORCE RLS on every Company relation, grants ordinary reads only through projected owner boundary and grants fixed functions to console_ontology_cmd. NOLOGIN writer cannot login/SET ROLE from runtime; no CREATE privilege on search_path. All functions schema-qualified, fixed pg_catalog search_path. Owner functions are fixed per registry and reject unregistered target kinds/legacy downgrade; wrappers cannot preconsume approval or mutate protected common objects through generic APIs. Trusted command service identity and credentials are a declared trust boundary, not a database-authenticated user boolean.
Deferred checks cover source/member/receipt in both insertion directions; pin/location/hold/retirement checks run on all actual writers before mutation, with fresh reads under lifecycle exclusion. Privileged migration/maintenance catalog operations are separately fenced and approved; application proof does not defend against superuser disabling triggers. Custody SQL shape in custody-schema.sql.txt plus these exact owner procedures is the proposed physical realization; actual clean/upgrade catalogs and adversarial SQL callers must be tested after approval.

Fixed owner procedure semantics
Each registered dispatcher row resolves an immutable input schema and one compile-time branch; family-sensitive source action verifies tag equality. Every new-effect branch uses OC28 ordered command/replay/current-source/protection validation then its explicit row set. Calendar writes calendar revision/head; assignment writes assignment revision/head with same Employment/calendar/date projection; coverage writes immutable coverage and complete day/source manifest; close writes immutable close basis and complete membership; proposal/verify/revoke use23 state graph and source-key projection; native prepare/calculation use18 complete header/member/monetary row correspondence; review/gate/case/transfer/Group rows use guards above and typed results. SQL entrypoint cannot trust caller-provided result values, counts or expected projections independently of prepared immutable owner rows/decoded input. Precompute is trusted domain calculation with exact build+input digest and final validation, not arbitrary prepared=true.
Common prepare allocates real retained unit+24 binding+receipt; seal binds exact one attempt/command/Account/input once; publish fills real bytes/digest/size and actual source effect; adopt creates exact result/purpose obligation and pins; consume gate writes one consumption correlated to same sealed command; finish attempt writes terminal exact receipt and work transition. All same-Company participants borrow same transaction. Any error aborts all; no worker later completes half a source receipt. Registered outbox effects use only committed remote-applied results under OR28 dispatch fencing. Duplicate exact command returns same result under current disclosure. Legacy paths affecting enrolled sources/drafts/gates/tasks either call these same owners or are unavailable; no force/maintenance UI exception.

Native preparation physical stage
native_preparations has PRIMARY KEY(org_id,command_id), unique(org_id,preparation_id), original Account FK, command fingerprint BYTEA32, action enum PREPARE_INPUT/CALCULATE_RUN, run FK, immutable expected/input-schema/build refs, state BUILDING/SEALED/ACTIVATED/CANCELLED, monotonic revision, optional sealed manifest UnitRef/digest, and optional final receipt ref. Worker claim ID/generation is fenced mutable owner control, not authority to impersonate Account. Append-only native_preparation_events keys(org_id,command_id,sequence) correlate each staging chunk/transition and exact preparation revision. No final receipt exists merely for BUILDING. Command replay compares original fingerprint before returning preparation state; same command cannot create two preparations. Prepared manifest/chunk storage reuses18 staged input/calculation membership and28 inventory; no second authoritative native data model.
Constraints: SEALED/ACTIVATED require complete immutable manifest; ACTIVATED requires matching final command receipt and native current/result membership under deferred checks; CANCELLED cannot later activate. Header/run/input/Company/employee keys are checked before attaching each staged unit. Ordinary queries only read committed active native heads through owner projection. All lifecycle changes serialize with original command/attempt guard. Exact mapped staged rows are excluded from current head and never cleared while a surviving obligation/pin requires them. These shapes are design requirements for later reviewed migration tests, not executed migration claims.
