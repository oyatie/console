결과에는 제출 증거가 반드시 연결되어야 합니다

준비한 보존 단위는 한 제출에만 봉인되고 다른 제출로 재사용되지 않습니다. 모든 원천 결과에 동일 명령의 제출 사본을 연결하는 보존 관계가 필요합니다. 연결이 빠지면 커밋할 수 없도록 양방향 외래키를 제안했습니다.

이력 연결과 실제 내용의 현재 보존 상태를 구분합니다. 완료 시에는 실제 사본과 독립 근거 보호를 확인하고, 나중에 허용된 내용 폐기가 이루어져도 결과·제출 이력은 유지할 수 있어야 합니다. 여러 결과가 사본을 공유하면 모든 적용 보존 의무를 확인해야 합니다.

기존 보존 객체에 제출 연결용 하위 구조 하나를 추가하고 공통 보존 관계를 재사용합니다. 새로운 삭제 서비스는 만들지 않으며 실제 삭제 경로도 이번 후보가 허용하지 않습니다.

구조 설계와 실제 보호 기능 구현은 구분합니다. 필수 근거 목록·현재 보호 상태·수명 변경 함수 통합, 실제 SQL 실행과 Verus 증명은 남아 있습니다.

  • 제약과 guard SQL 제안
  • 상태·화면 연결
  • 대안 비교
  • 비실행 검증 후보
