입력한 자료와 실제 결과가 어긋나지 않도록

기존 원천 버전과 명령 결과를 양방향 외래키로 연결합니다. 별도 버전관리 엔진·후속 관계 테이블은 만들지 않습니다. 기존 객체 선택·자동 채움·공통 초안 화면을 유지합니다.

검증 전에 철회한 자료와 검증 후 철회한 자료를 실제 이력으로 구분합니다. 새 자료로 교체한 뒤 그 새 자료가 철회되어도 이전 자료가 자동 복원되지 않습니다. 과거 연결은 남고 현재 사용 가능 여부는 별도로 판단합니다.

충돌에서는 허용된 입력을 보존하고 차이를 확인합니다. 실행 결과가 불명확하면 같은 명령의 결과부터 확인합니다. 기본 DB 오류 상세는 민감정보이므로 화면·로그에 전달하지 않습니다.

이 후보는 구조 설계입니다. 전체 원천 테이블·업무 의미·Cedar·보존·실행 함수·마이그레이션이 완성된 것은 아니며 실제 SQL 실행·제품 테스트·Verus 증명은 수행하지 않았습니다.

  • 저장·상태·복구 계약
  • 구체적 외래키 SQL 제안
  • 대안과 선택 이유
  • 기존 화면과 연결
  • 비실행 검증 시나리오
  • 닫힌 범위와 남은 일
