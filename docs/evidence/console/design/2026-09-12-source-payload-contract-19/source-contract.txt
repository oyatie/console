Reuse18 scalar/reference conventions and15 owning source revisions/heads. source-types.schema.json closes the calendar, assignment, coverage, leave payroll disposition, qualification/credential, eligibility, tax and close payload shapes for source19-v1. Shape closure is not full F01/F02 closure: source package/adoption/Account/whole workflow SQL, issuer/normalizer supply and command/ACL implementations remain explicit. No new money calculator, source-specific approval engine, job-title roles or runtime LLM interpretation. Business source kind/purpose controls decoder and applicability; it never grants authority. Automation and manual repair call the same registered owning action with identical validation, current policy, draft/review/effect/receipt semantics.
Exact current identities:0091 events use (Company,id), no version;0188 exception resolution/close/amendment rows also use immutable UUIDs, no revision sequence. Never invent revision1 or xmin as source version. Correct15's implied existing amendment_revision:19 OperationalCloseRef carries exact close, sorted complete amendment UUID set and its commitment, plus actual Company period lock. The native close-basis record still has its own proposed revision;18 refers to that basis and needs no byte reinterpretation. Native source19-v1 is a new registered codec, not a rewrite of prior source15/18 fingerprints.
CalendarRef/CalendarAssignmentRef use15 owner roots/revisions. DispositionRef maps disposition_id to a registered common instance revision (instance_id,version) owned by leave; generic instance mutation cannot author it. No new independent leave decision engine/table: the leave owner projects exact current request/charge/decision audit/policy into this immutable typed object. Existing charge resolution and audit_event refs retain their real IDs.19 selects the object representation; exact common type/owner dispatch/ACL/storage enrollment remains F01/F02 integration. Historical actor attribution is a closed LEGACY_COMPANY_USER or ACCOUNT witness; never create a fake user/Employment to fit an Account. Existing event actor migration remains13/F05. A legacy actor ref proves provenance only, not current authority.

SP19.2 Calendar and coverage
Calendar publishes a finite1..366-day half-open range, seven unique ISO weekdays and unique dated overrides inside coverage. Override wholly replaces that date's plan; there is no ambiguous field merge. Dates outside coverage are unknown. Current profile zone Asia/Seoul is a calculation coverage constraint, not an assumption every Console calendar globally uses it. Minute offsets are integer0..2880 from local anchor midnight; start<end and each duty<=1440minutes. Duties and breaks are sorted, nonoverlapping, breaks contained in their duty; effective duties across adjacent anchor dates must not overlap. WORK_DUTY needs duties; other kinds have none. Expected work/paid minutes are checked against the exact current qualified time rule and normalized intervals, not accepted from a tenant total. Rest/holiday paid duration requires its own qualified basis. Unknown time rules block publication; partial entry stays a common private draft. Split/shorten finite publication range automatically when normalized payload exceeds64KiB; preserve explicit assignment intervals and reviewed revision, never truncate exceptions or silently alter an existing published calendar.
Resolve exactly one effective active calendar assignment per Employment/date, with no gap/overlap. A current head alone is insufficient for historical selection; retain prior assignment revisions and exact calendar. The existing WorkCalendarPort must gain/participate in a borrowed-connection owner read so guards and source reads share the same transaction. It currently supplies no such guarantee. Capture complete source semantics; promotion within the same Employment can keep several historical segments. A different employer/Company or site label is not interchangeable source identity or authorization.
Coverage uses every earning date, selected anchored calendars and exact event and classified-day packages, leave dispositions and qualified rules. COMPLETE requires full period28..31days (all real dates once sorted), nonnull exact source package, known independently established opening boundary, no blockers, and complete interval classification and obligations under qualified rules. BLOCKED requires nonempty root blockers and may retain complete known days in a coverage-day package or no package; root outcome cannot be COMPLETE with blocked days. No fake amount or assumed absence of overtime. CoverageInterval work/paid-break/absence durations exactly partition the relied-on duty without double counting; unpaid breaks/off-duty are never paid minutes. PAID_REST/PAID_HOLIDAY may have no event intervals but paid duration follows their declared qualification, not work duration. Unscheduled or outside-duty events remain considered and block unless an explicit qualified disposition resolves them.
Pair complete clock events in owner order, preserve OUT_FOR_WORK/BUSINESS_TRIP/RETURNED as classified facts. Use strict_pair_seconds only after exact subminute precision checks and filtering wholly disjoint pairs before clipping; the current helper is not a paid-time calculator. Minutes from rounded ot_hours NUMERIC or formatted floats cannot be reconstructed exactly. Unknown precision or unsupported >24hour shift blocks. Expected/covered durations are server derivations from immutable references; neither matching counts nor CONFIRM exception creates paid time. Day intervals and totals are checked, not user assertion.

SP19.3 Leave disposition is more than balance charging
0166 request_version is current workflow CAS; charge_version identifies immutable charge resolution. Actual decision path is0217 approve/time_change. time_change_consult clears current charge pointer/units while preserving old charge evidence; alternative-date proposal advances request_version. Therefore an old charge resolution cannot prove currently effective leave or paid minutes. LeaveDisposition binds Company/employee/Employment, exact request_version, current matching charge tuple, immutable decision audit event, canonical request snapshot digest, exact interval, qualified pay rule and relied-on artifacts. Resolve current leave owner state under LEAVE guard: only currently effective approved dates/intervals and matching charge/decision qualify as PAID; consultation/pending/withdrawn/changed or missing evidence is UNRESOLVED, never automatic unauthorized absence or zero-pay. Current absence collection must include consultation and other unresolved states, not only the old pending count.
Decision audit must be exactly leave_request.decide with same Company/request and matching before/after request/charge/status transition; supplied audit UUID or newest timestamp alone is not proof. Existing audit snapshots do not hold every interval/payroll fact.19 requires the leave owner to capture the full typed current decision witness in the same transaction as its native projection and preserve original audit+source custody. Legacy requests without provable interval/version linkage remain unavailable for this source profile until a governed current resolution; do not manufacture historical evidence. Charge encoding LEGACY_PG_JSONB_TEXT_V1 preserves the0166 server_digest bytes; SOURCE19_V1 uses its new declared schema. Do not relabel a legacy hash or infer paid minutes from day units. Existing absence exceptions are immutable IDs and diagnostic evidence; CONFIRM alone cannot satisfy the qualified leave/paid-time rule.

SP19.4 Qualified source and verifier trust
Qualification union has exactly TAX_TABLE, APPLICABILITY_RULE, WORK_CALENDAR_RULE, RULE_BUNDLE, REVIEWER_CREDENTIAL. Citation/source_url is display metadata. Artifact original/derivative identity, immutable edition, finite applicability and qualified review evidence are required. Compiled RuleBinding maps purpose/version/body hash to a deployment-admitted pure rule; an uploaded string or tenant object cannot install code, percentages or legal conclusions. APPLICABILITY_RULE purpose must match the requested obligation: taxable-income definition, pension basis definition, insurance remuneration definition, insurance applicability, no-adjustment coverage, paid absence, calendar paid-time or tax selection. WORK_CALENDAR_RULE time bindings require CALENDAR_PAID_TIME/PAID_ABSENCE_TREATMENT; TAX_TABLE selector/combination require TAX_ROW_SELECTION. RULE_BUNDLE refs may name only the direct TAX_TABLE/APPLICABILITY_RULE/WORK_CALENDAR_RULE inputs; never another bundle or arbitrary recursive graph.
Professional verification follows source -> reviewer credential -> deployment-owned pinned issuer profile -> exact issuer artifacts. Credential authenticity is verified by an independently identity-verified Cedar operator under that issuer profile; reviewer_credential_ref MUST be null for that special authenticity verification. It is not recursion through another professional credential, and operator privilege does not make the operator a professional reviewer. Other source/eligibility/tax verification requires nonnull current REVIEWER_CREDENTIAL for the actual verified person, exact purpose/Company/scope/date. Proposer/verifier are different AI1 verified humans, regardless of Accounts or titles. All referenced credentials/issuer profiles remain currently valid, unrevoked and independently grounded. No tenant admin or self-signed evidence bootstraps trust.
Required closure bound: no recursive general walk; max32 direct refs per list, max256 distinct qualified-source/credential/profile/artifact nodes in the compiled dependency plan, max3 qualification edges before issuer artifact. Exceed/missing/cycle/unsupported profile denies new use; do not stop after a convenient subset. Actual source supply and professional/issuer authority remain separate readiness inputs, not invented source fixtures.

SP19.5 Eligibility and tax semantics
Eligibility binds exact EmploymentCoverage, stable corrected wage, complete coverage, period/pay_date/profile, each of four employee deduction schemes, explicit pension/insurance remuneration/taxable bases, all seven named obligation families and tax selection facts. UNKNOWN, NOT_APPLICABLE, DUE or UNRESOLVED remain facts rather than silently false/zero. Current kernel has no insurance applicability switches: NP1 SUPPORTED requires all four APPLIES, no adjustments, explicit pension basis (Some, never None->gross), supported wage/hours/minimum-wage evidence and exact bases. Employer industrial-accident amount remains uncomputed; employee-only nonpayable output is not full employer payroll/compliance. SUPPORTED has no blockers, all amounts and selection present, and all insurance/obligation sources valid. BLOCKED has nonempty blockers; unknown basis uses null and selection is null if its exact taxable/family facts cannot be established. Do not invent zero just to satisfy a shape. Missing core Employment/wage/coverage stays in common draft or18 BLOCKED input, not a fabricated assessment ref. Verification of an eligibility admission requires SUPPORTED current semantics; a blocked proposal cannot become an executable source by checking attestation.
Assessment depends on source facts, never later tax evidence or run close. Tax admission depends on a current verified assessment and exact source edition/artifact, selection and locators. Tax selection counts1..99/0..99 and P80/P100/P120 are wire bounds; supported combinations and any child/dependent relationship come from the qualified edition rule, never an invented legal inference. Taxable amount must equal assessed taxable basis, not assumed gross; pension/insurance remuneration bases must match what existing kernel actually accepts for the profile. Amount_stage FINAL_WITHHOLDING means all qualified option/child/note adjustments already reflected; do not apply them twice. Local tax is an independently located/qualified amount, not income_tax/10 by assumption. Both final amounts nonnegative checked i64 won; unsupported negative net/rounding blocks under18.
Source selection is complete0/1/many across matching current roots including hidden competitors. Exact identity/basis differs even if amounts coincide. No latest-root tie-break. Every new downstream use revalidates current bounded trust and source closure under guards; retained historical receipt replay remains governed by current disclosure, not re-execution permission. Revocation does not erase old evidence or recreate lost rights. All source snapshots, notes and artifacts are subject to current field/resource disclosure before rows, counts/hashes, links, SSR/hydration and notifications are serialized.

SP19.6 Exact purpose and incomplete entry
AssessedAmount definition_ref resolves a current APPLICABILITY_RULE with TAXABLE_INCOME_DEFINITION for taxable_basis, PENSION_BASIS_DEFINITION for pension_basis, and INSURANCE_REMUNERATION_DEFINITION for remuneration_basis. InsuranceFact requires INSURANCE_APPLICABILITY; ObligationFact NONE_DUE requires NO_ADJUSTMENT_COVERAGE for that exact family. A verified rule with a different purpose cannot substitute. The tax selection income_definition_ref equals the assessed taxable definition. These are decoder/purpose constraints of this initial supported profile, not an exhaustive Console business taxonomy.
A LeaveDisposition with UNRESOLVED treatment may be published only when all its request/charge/audit witness fields really exist and correlate; it records uncertainty about pay treatment, not a missing decision. Pending or consulting requests with no matching current charge/decision remain common draft plus typed LEAVE_REQUEST coverage blocker. Never manufacture required fields. Missing qualifications/evidence in any source similarly stays in the common draft; a BLOCKED payload is not a universal container for absent required references.
Calendar auto-splitting prepares proposed finite publications and matching assignment changes in the common reviewed draft, showing their combined effective dates. It cannot activate a shortened calendar or gap before all covering assignment/publication changes validate and commit atomically within the Company. Existing published revisions remain immutable. Failure preserves previous assignments.

SP19.7 Calendar obligations across midnight and month boundaries
For each earning date D use the exact ACTIVE assignments and published plans for D and D-1 in Asia/Seoul. Offsets0..2880 mean no earlier anchor can positively intersect D. Read first earning date minus one through the last earning date; include the next boundary plan when validating cross-boundary overlap. Missing prior assignment/plan is unknown unless exact Employment-start and qualified initialization evidence establishes that no prior duty exists; no guessed next-day plan. Resolve overrides as whole replacement before allocating. The same assignment need not own both dates, including a month-boundary assignment change.
EffectiveDayPlan is exactly {org_id,anchor_date,calendar_assignment_ref,calendar_ref,plan}; plan is the closed ResolvedDayPlan without weekly/override selector fields. plan_digest=H("console.source19.day-plan",EffectiveDayPlan). It commits the actual assignment, calendar revision, effective date, normalized duties/breaks/totals and qualified rule. Never hash a raw unresolved weekly selector or a tenant-supplied total without checking it.
Convert anchored duties/breaks to exact instants, intersect with [D00:00,(D+1)00:00), and allocate each positive interval once. A WORK/PAID_BREAK/PAID_ABSENCE interval names its contributing plan_anchor_date; OFF_DUTY/unscheduled evidence may use null but cannot count toward a claimed duty. Qualified non-duty rest/holiday paid obligations belong only to their own anchor date. Day plan_contributions contains current date (even a known nonworking declaration) plus previous date when it contributes a positive duty intersection, sorted by anchor_date and duplicate-free, max2. At COMPLETE every expected work/paid total equals sum of these clipped contributions, and covered totals equal classified interval/rule derivations; unknown classification or overlap blocks. A BLOCKED day may omit an unavailable contribution with a typed blocker; it never proves absence of obligations.
Example: Aug31 22:00-Sep1 06:00 contributes480minutes to the whole shift and360minutes to September1 from the Aug31 assignment. A Sep1 09:00-18:00 plan with60minutes unpaid break independently contributes480minutes under Sep1 assignment, so September1 expected work=840. A Sep30 22:00-Oct1 06:00 duty contributes120minutes to September30;360 belong to October. Qualification and supported NP1 hours are still checked independently; arithmetic is not legal approval or profile eligibility.

SP19.8 Full classified-day custody within finite bounds
Classified days use the same Docs artifact/adoption mechanism as event/member packages: CoveragePayload names coverage_days_ref, never embeds an arbitrarily large whole month. COMPLETE requires nonnull event and day package refs and exactly every real earning date once, with no day/root blockers. BLOCKED may reference a package of known whole days or null. Day count/package header/Company/employee/Employment/period/event-set digest must correlate exactly with CoveragePayload and selected event package; no package from another snapshot. All interval event_refs resolve in the selected event package. No day/package hash is authority or a completeness assertion by itself.
Each classified day remains a bounded leaf, not a new business writer or action. Publish coverage + event/day artifact adoptions/pins + receipt atomically after guarded source re-resolution; build/upload/attest both outside locks. A day exceeding64KiB,32intervals or2contributions cannot be silently split into duplicate dates: retain source event custody, omit that entire invalid day from a BLOCKED package and emit a bounded root SOURCE_BOUND_EXCEEDED blocker. Root leaf overflow emits a compact BLOCKED payload with null day ref and a single bound blocker, retaining exact event ref when it fits; no truncated COMPLETE or discarded historical record. Operational repair remains the owning source action; supported contract widening is a reviewed change, not manual bypass. Ordinary five-interval days do not overflow a monthly64KiB limit because the monthly day stream is framed separately.

SP19.9 Exact opening instant and anchor use
CoverageBoundary.opening_state is the verified state immediately BEFORE query_from_us, not an unqualified assertion about earning_start. Query interval is [query_from_us,query_to_us); replay events at query_from after initialization and replay in-window events through earning_start to derive the earning opening state. A prior anchor is the exact last owner event strictly before query_from; if used, its state_after seeds opening_state. No anchor and no independently qualified initialization evidence means UNKNOWN. The anchor is preserved in package custody but excluded from strict-pair event input when used only to seed state (an earlier CLOCK_OUT must not create an unmatched OUT). If state is already on-duty at query_from, the actual prior CLOCK_IN/pair lineage and exact<=24h support must be proven by the owner; an OUT_FOR_WORK/RETURNED anchor alone cannot invent the missing start. Otherwise BLOCKED. The V13 OFF_DUTY seed is at Aug31 00:00; replaying the Aug31 22:00 CLOCK_IN gives CLOCKED_IN at September1 00:00.
