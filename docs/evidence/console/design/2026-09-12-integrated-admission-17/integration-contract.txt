IC17.2 Concrete native input shape and immutable lineage
A PopulationSlot is keyed (org_id,run_id,input_revision,employee_id); coverage is one exact Employment identity with segmented full-period refs underNP1. Variant RESOLVED requires EmploymentCoverage,WageFact,AttendanceCoverage,Eligibility,TaxEvidence,Profile/RuleBundle and declared taxable/insurance bases. Variant BLOCKED requires a nonempty registered blocker code set and exact available partial source refs; it forbids a fabricated resolved calculation-source digest/amount. Visibility is not a third variant or a filter. All source payload definitions and precise nullable SQL columns remain explicit F01/F02 closure work, not arbitrary JSON. Company/run/input/employee keys must match on every native child FK.
payroll_input_revisions and payroll_calculation_batches append even when every required slot is BLOCKED. Empty required population cannot close. Only RESOLVED slots can be referenced as calculated lines; current batch membership excludes stale/orphan legacy rows. Existing payroll_line_calculations receives exact input/batch refs and no new monetary truth is written to a parallel engine. Same-run current input/batch pointers require exact composite FK/deferrable owner-constraint checks; legacy rows keep LEGACY protocol and unknown provenance, never get backfilled VERIFIED.
Draft payload lifetime is separate from identity. Introduce one shared retained payload identity registry (Company,typed unit ID,version/whole-chain selector,digest when meaningful) and pins/adoption/disposal control through RR17, not one retention mechanism per module. Domain refs that must remain readable point at retained submitted evidence/artifacts; lineage-only draft revision refs can survive as immutable IDs/tombstones and must not be permanent RESTRICT FKs into physically disposable payload. An owner cannot release a pin by merely changing a link label to 'lineage'.
