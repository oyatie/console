WP17.1 Current harness reuse and its limits
Reuse platform/test-support runtime_role_pool and existing domain/REST/RLS/owner tests; they preserve valuable behavior regressions. That helper connects through an owner-derived DSN then SET ROLE console_rt; sqlx tests migrate as admin. SET ROLE does not inherit login role defaults and can hide console_app default ACL behavior. Required separate PostgreSQL18.4 fixture uses actual deployment migration entry CONSOLE_APP_ROLE=migrate directly authenticated as console_app; business/read tests authenticate directly as console_rt and each admitted command/auth role. Capture current_user AND session_user, search_path, role settings, database overrides, effective ACL and SET/RESET ROLE attempts. Runtime RESET ROLE must remain the same low-privilege login, not reveal the administrator behind a test pool.
Existing owner_only_acl_is_effectively_private_on_postgres18 test is ignored by default and CI explicitly invokes --include-ignored --test-threads=1. Its owner-side inspection is necessary but not sufficient for every new direct-login negative. Never count ignored/discovered-only tests as executed. Keep fast sqlx/domain tests and a separate production-role/upgrade/recovery tier; no weakening existing tests or migrating as superuser to bypass missing topology. One serialized schema/role bootstrap per disposable cluster. Preserve exact Cargo feature/target and discovered/executed counts; no invented passing target names in this packet.
