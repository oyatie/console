RM17 — Real privilege boundaries, one compatible migration order
RM17.1 Role and trust contract
Current0031 defaults grant future console_app public tables runtime DML. Every protected control/payload/credential table must REVOKE inherited runtime and PUBLIC privileges in the same creation transaction, then grant only declared operations. Catalog annotations do not change effective ACL. Read back owner, ACL/default ACL, schema CREATE/USAGE, role membership/INHERIT/SET, SECURITY DEFINER owner/search_path, trigger functions and force-RLS on actual migrated catalog. Include future tables created by each allowed migration role, not only hand-picked examples.
Reuse the governed command pattern from0206: direct LOGIN command credential, NOLOGIN confined writer, ordinary console_rt, migration owner and operational administrator are distinct. Command role cannot SET ROLE to writer/migrator or own/alter protected functions. SECURITY DEFINER entrypoint owns a complete validated owner command and calls private borrowed helpers; fixed search_path=pg_catalog with schema-qualified objects, no caller SQL/identifiers or allowed=true. Runtime has no direct DML over protected control fields, no direct EXECUTE on private helpers and no schema CREATE path to shadow an object. Immutable facts reject UPDATE/DELETE except specifically named one-way metadata transitions, such as common interval close or basis submission NULL->exact request. Function writer may have only the DML needed by its owned protocol; function owner privilege is not business authority.
Application authentication/Cedar and the execution service remain trusted. SQL functions do not magically execute Cedar or authenticate a caller by accepting p_actor; one shared process alone proves nothing. Public request never chooses trusted actor/Company/policy verdict. Owner command entry receives server-validated current identity and exact registered inputs; all independent structural/source/current-state/command/guard checks are enforced at their owner boundary. Credential theft/compromise of the trusted auth/execution service is not claimed prevented by an actor column. F04 must bind the actual service-to-command credential/pool topology, parameter provenance and direct-call denial before activation, rather than inventing an unverifiable SQL 'authorized' marker.
Account/auth data is a distinct protected authority root; console_rt and employer helpers cannot read keys/refresh material or suspend global identity. Group controls are owner-only and never use a sentinel Company or arm app.current_org=Group. All Company domain operations remain one RLS cell with composite FKs; Group capacity helpers may touch narrow control refs within that transaction, not another Company's salary/personnel rows. Enrolled aliases such as legacy Group p_actor/p_user functions must delegate guarded Account-aware owners or refuse. Actor anchors survive departure; foreign keys do not force fake Company users or delete Accounts with organizations.

RM17.2 Expand/backfill/enroll
M0 catalog/source inventory before any change: exact schema/code hashes, roles/functions/defaults/constraints/triggers/actor FK dependency graph, protocol/receipt formats, retained payload copy inventory, legacy active payroll reservation census. Preserve unknown rows as blockers; inventory is not automatic evidence qualification.
M1 additive Account/security/CompanyActor and guard roots, policy/identity revisions and immutable action/codec registration. New surfaces default disabled. Install global legacy-auth refusal and drain already accepted legacy sessions/streams/refresh writers BEFORE inserting account_security cutover rows. Its existence permanently fences legacy authentication even if state later becomes ACTIVE again. Account security migration is its own cutover cell, not deferred to individual Company toggles. Do not lower current generations on rollback.
M2 source/native payroll records and named constraints: corrected wage resolver on every reached reader, source-family fences, historical coverage, exact input/batch identities, supported selectors and overlap reservation semantics. Existing payroll_draft_runs remains owner; legacy payable/issuance paths cannot bypass new review protocol. No old result relabelled verified.
M3 common draft controls/attempts plus shared retained-unit/pin/adoption/disposal control and compatible projections. Quarantine-aware readers and deny aliases precede enabling sensitive drafts/disposal. No generic 'draft' lifecycle classification is sufficient to authorize deletion. New independent current journal and recovery-source proof required before physical cleanup enrollment.
M4 reusable workflow/Group/governance/review/publication records and participating transactions; complete all actor FK/default grant/registered dispatch changes. One payroll basis->common request binding, original governance decisions, and one accountable workflow assignment; do not copy generic decisions/work histories into new domain tables. No source-only deployment enables a half-wired task/receipt/gate path.
M5 resumable backfill and read compatibility: stable primary-key range/checkpoint, idempotent batch command and exact pre/post source identity/count comparison. Expected input rows = mapped rows + explicitly quarantined blockers; no skipped residuals. Use at most500rows/4MiB and2s statements initially, repeat same batch ID after conclusive rollback only. Size exceptions stay blocked for a reviewed handling path. Backfill cannot mint live grants/people/credential trust/legal source facts or erase legacy deny state.
M6 exact enrollment after compatible binaries/readers/projections/source writers and proofs are present. Each unit is (control plane Account or Group, or Company + registered object/action/read surface + protocol revision), not persona/title/reason. Activation manifest includes exact schemas/binaries/codec/policy/query plans, direct aliases, source writer closure, recovery generation and proof receipts. Read/write/history/export/SSR/hydration/outbox/background paths are covered; hiding a button is not closure. If serving pool has any unsupported version, pause affected admission and drain before enabling. Run migration/backfill as one writer; do not run startup migrations from all serving replicas.

RM17.3 Admission record and rollback
Add small platform/db-owned deployment_admission_generations and admission_events protected control records: monotonic serving generation, exact manifest digest, compatible reader/writer versions and PAUSED|ADMITTED state. A Company protocol flag references the exact admitted generation, not an unversioned enabled boolean. Account cutover fence remains permanent and separate; pausing a Company never makes old Account tokens valid. Actual independent serving-generation authority for recovery is RR17; local generation alone cannot fence an older restored deployment.
Admission failure stops new effects/read surfaces requiring the failed proof and retains permitted Account recovery/history where its current proof survives. After first new-format record rollback uses a known-compatible binary with new mutations paused. It preserves source corrections, heads, Account identities/revocations, Group incarnations, current disclosure state, command receipts, unknown attempts/capacity/pins, journal/readmission and tombstone readers. Do not DROP tables, reset revisions, restore old grants, repeat unknown effects or serve an old snapshot as a rollback shortcut. Before any destructive job, unused additive schema can remain dormant; after deletion begins only forward-compatible recovery/repair can restore operation.
