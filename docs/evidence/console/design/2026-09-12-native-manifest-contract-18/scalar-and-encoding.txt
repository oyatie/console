NC18 — Native scalar and commitment contract
Reuse CCF1 restricted canonical writer14. Raw UTF8 input must reject duplicate keys before JSONB/Value, JSON numbers, invalid UTF8/unpaired surrogates, decoded NUL, unknown fields, excess bytes/depth and unsupported discriminants. Strings have no implicit trim or Unicode normalization. Canonical UUID is lowercase hyphenated nonnil; native18 wire rejects noncanonical spelling. Date is an actual Gregorian YYYY-MM-DD, selected profile range verified by owner. Decimal signed i64 is -9223372036854775808..9223372036854775807, no -0/leading zero/plus/fraction/exponent/whitespace; PositiveRevision excludes0, NonnegativeWon includes0, PositiveWon excludes0. CalculationRevision is1..2147483647; Ordinal0 is0..255 and selected/candidate constraints tighten it. Pattern+length in JSON Schema is lexical screening, not checked numeric/date validation.
Every required nullable field must be present; missing and null are distinct. All refs must resolve in the same Company and correct owner/type/subject, including profile/scope object revision and rule bundle. The earning interval is [Asia/Seoul local month start, next month start); preserve UTC microseconds without submicrosecond rounding. pay_date is explicit separate Date. Segment from<to, sorted contiguous, exact clipping and complete eligible one-Employment coverage; version order is not effective-time order. Wage correction0 maps base, positive maps exact correction. Kind/selection/ordinal and all subtype fields are committed, not just target UUID.
Canonical keys sort ASCII bytes, Unicode escaping follows CF1 exactly. source_refs sort by ASCII(kind), then ASCII(selection), then integer ordinal; candidates additionally assigned ordinal by canonical ref bytes. blockers are a set sorted by their canonical bytes; source_slots within each blocker are a set in kind/selection/ordinal order; duplicates refused. Employment selected segments use increasing from_us, never UUID/version sort. Fixed header/source-family witness arrays sort by registered family ASCII. These normalization rules are codec native18-v1; old protocol digests stay unchanged.
Leaf framing: H(tag,object)=SHA256(UTF8(tag)||0x00||CCF1(object)). Tags are console.payroll.native18.source-ref, console.payroll.native18.unit-semantic, console.payroll.native18.unit-custody, console.payroll.native18.input-header, console.payroll.native18.calculation-outcome and console.payroll.native18.batch-header. Each leaf encoded size<=65536; no JSON numeric value; max depth8; per-list declared bounds<=256. Length/ref cardinality/semantic checks precede hashing. Digest equality never grants permission.
Unit semantic object is exactly {org_id,employee_id,context,basis}, context={period,pay_date,earning_zone,earning_start_us,earning_end_us,profile_ref,scope_basis_ref}, basis={resolution,source_refs,arithmetic,blockers}. A RESOLVED arithmetic object is the exact native schema. Unit custody object is exactly {org_id,run_id,input_revision,employee_id,line_id,semantic_digest}. Family witnesses and preparation attribution live in InputHeader (schema), whose commitment uses input-header tag. Source-ref tag hashes one NativeSourceSlot including selection/ordinal. These hashes are distinct from command fingerprints and from source-owner revision digests.
Large input framing is streamed, not a >256-element CCF1 command: SHA256(UTF8("console.payroll.native18.input-manifest")||0x00||header_digest_raw32||U32BE(unit_count)||for each employee ordered by raw UUID16: employee_uuid_raw16||unit_custody_digest_raw32). unit_count<=2000; zero allowed only as a blocked empty preparation, never close/calculation. Input header membership_count must equal enumerated owner population and exactly persisted units. Aggregate body not sent as command input; command uses an immutable manifest reference. Peak retained leaf bytes remain bounded; no concatenating all2000 leaf JSON documents.
Batch framing similarly SHA256(UTF8("console.payroll.native18.calculation-batch")||0x00||batch_header_digest_raw32||U32BE(outcome_count)||each employee_uuid_raw16||outcome_digest_raw32 in UUID order). BatchHeader is exactly {org_id,run_id,calculation_revision,input_revision,input_manifest_digest,close_basis_ref,actor_account_id,command_id,recorded_at_us,member_count,success_count,blocked_count}; all numbers strings. Outcome object is exactly {org_id,run_id,calculation_revision,input_revision,employee_id,line_id,input_unit_digest,state,result_ref,blockers}. input_unit_digest is exactly the referenced payroll_input_units.custody_digest, never semantic_digest. Its Company/run/input/employee/line tuple and digest are enforced together by the outcome composite FK; owner/deferred validation independently checks canonical recomputation. Result_ref is null or {calculation_id,version}; it references immutable existing money, whose owner integrity/readback contract must be verified, not reimplemented as a second monetary ledger. Outcome equality/digest does not by itself certify the amount row immutable against a privileged owner; runtime write confinement is mandatory.
Literal vectors in normalization-vectors.json are evidence reference bytes/hashes, not product tests or proof Rust/JSONB follows this contract. They cover correction0, Korean note escaping, absent/null rejection boundary, input order/semantic-vs-custody distinction and large framing structure. Approved tests later compare independent literals against Rust + DB readback, strict decoder failures, corruption and hostile refs.
