## Transaction A

After initial Auth/current-source/Cedar, adapter binds selected Company GUC and invokes frozen prepare_v1 with exact bytes/selectors. New input receives exactly one typed Account acceptance audit through common writer; replay receives none. Prepare returns original selected input plus optional terminal. Adapter parses exact13/30 fields, checks shape and selector/decoded bytes/digests against original actor/Company/operation. It drains deferred constraints then repeats original mutation proof, current Auth/source/Cedar/time and commits. Lost COMMIT response is Unconfirmed. No B may start after any A error or uncertainty; no accepted view is returned before confirmed A commit. Capacity/preflight failures remain nonterminal errors, not durable rejection codes.

Acceptance NotVisible is a malformed owner result (Unavailable); pending/expired retain exact typed original input; existing terminal is authoritative after current disclosure and receipt validation. A replay never re-encodes historical bytes as a successor codec or applies quota again.

## Transaction B and recovery

The convenience submit usecase awaits A finish and release. If A returned final terminal, return that exact terminal with inserted=false without B. Otherwise open a new B using the same credentials and selector only, fresh lock plan/Auth/current Cedar; no input bytes or replacement expiry/recipient/revision are accepted. Adapter invokes frozen execute_v1; new terminal gets exact common complete audit (plus install event where required), closure and final checks then commit. Existing final gives inserted=false, no effect/audit rewrite. Known late error rolls back B leaving A; commit uncertainty returns Unconfirmed, never success or generic durable rejection.

Status is a separate no-write usecase with current read credentials and exact-operation disclosure. It waits through owner serialization, validates one of NotVisible/AcceptedPending/AcceptedExpired/final, finalizes and returns. It never executes, expires, clears or repairs. A later explicit retry uses execute with the same selector and freshly captured valid mutation credentials; no fresh command identity or replacement bytes. Lost-response recovery cannot assume the first attempt failed. AcceptedExpired may be executed to obtain the canonical intake_expired terminal; status alone never synthesizes one.

Terminal parser preserves four rejection codes only (intake_expired,revision_conflict,grant_expiry_invalid,recipient_ineligible), exact typed input, receipt/epochs, actual effect IDs/state/interval and actual execution time. Internal transaction IDs, session IDs, raw bytes/digests/designation proofs are not view DTOs. The full SQL13/30 shape remains the adapter's checked source contract, not an HTTP serialization contract. Current source corruption, missing auth, evaluator failures and unexpected SQL are faults/denials, never durable rejection.
