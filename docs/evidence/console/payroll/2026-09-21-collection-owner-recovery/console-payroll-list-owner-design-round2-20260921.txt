## Demonstrated defect and exact result semantics

`PayrollRestState::visible_run_summaries` (rest/lib.rs133) converts every `list_runs_page` error into `Vec::new`. `app::compose_ui_screens` separately calculates `floors.payroll` and calls `ScreenSection::from_authorized_listing`, so a real authorized SQL/audit failure becomes an empty success. The already implemented Failure/retry presentation is unreachable from that path.

Required outcomes come from **one owning read operation**, without trusting an independently calculated App floor:

| Evidence from same path | Authorized projection |
|---|---|
| Missing/invalid credentials, denied policy, or inability to establish current authority | Omitted; no payroll section, existence/failure marker, row or payroll navigation |
| Current authority established; successful committed read with0items | Empty |
| Current authority established; successful committed read with items | Rows |
| Current authority established; subsequent query/audit/commit failure | Failure, actual `/payroll` retry; no partially loaded rows or count |

The compatible JSON route retains its existing authentication/denial/error status and envelope. Only the SSR helper maps inability to establish authority to omission. A render-time auth flag or an earlier listing-floor success cannot turn a later failed authorization into visible failure.
