# Exact source-bound proof preparation

This is an authored harness and checker, not an executed Verus proof. Null bindings explicitly mean the ordinary production owner does not yet exist at the pinned base. Preserve the earlier supplied-value proof and its tool pins as historical evidence; it is not substituted for this source proof.

The integrator binds each of four owners to exact commit:path, blob, entire file SHA, executable spans and SHA, byte-identical extraction, and every actual caller. The actual payroll current read caller, JSON/SSR renderers, cache builder, live frame scheduler, preprojection request-event scheduler and bound transport must appear in the external-relation census. The projector source type is plain data; current context and policy decisions are opaque ordinary-owner capabilities. No Deserialize, literal, unchecked constructor or test-only conversion may create them.

Reviewer verifies that all executable source spans and all relevant struct fields are complete and that the extracted code actually executes the same path. The checker proves byte identity only after that review; it cannot determine complete AST/FFI/data-dependency closure. Every assume, external_body, external_fn_specification, admit, axiom, unsafe, FFI, trusted loader, policy call, serializer, emitter and transport is enumerated with exact location and owner. Unresolved production boundary is an implementation prerequisite, never an assumed low-equivalence output. `allowed_source_view` maps actual permitted fields, presence/absence, ordering and public shape; it must not be output equality or a caller supplied allowed=true.

Projector counterfactual source tests preserve every input field except one denied scalar. They separately bind actual two-member persisted line IDs and real decisions, actual current read caller, positive allowed-field variation, and all concrete sink encoders. This is a composed boundary proof, not a second persisted same-line tax world. Full wire integration and each enabled adapter remain required before adapter acceptance; serializer-level equality is not called socket/browser execution.

`negative-recipes.json` specifies finite actual-owner mutations. Review the concrete patch only once actual source exists, record exact baseline/mutant hashes, and populate six proof_runs with pinned source hashes and designated diagnostic anchors. Bind actual Verus, rust_verify, Z3 bytes, Rust version and exact Cargo features. Run `python3 -B proof-harness/source_binding_gate.py proof-harness/binding-final.json /path/to/isolated/exact-checkout`. The runner uses a fixed argument vector without a shell, saves raw verifier logs, requires the exact six run names and nonzero verified units, rejects import/parser failures, and requires the designated assertion/postcondition location for each negative. No fabricated completed verifier output may fill these rows.

`python3 -B -m unittest -v test_source_binding_gate` executes synthetic CHECKER controls only. Synthetic function bodies in that test never serve as production proof inputs. A source-only syntax check of the Rust harness is not possible through rustfmt expansion because bound_owner.rs intentionally does not exist; Verus syntax remains an implementation/toolchain prerequisite.
