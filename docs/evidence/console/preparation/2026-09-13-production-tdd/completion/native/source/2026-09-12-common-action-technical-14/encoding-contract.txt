CF1 — Versioned deterministic command and revision bytes

CF1.1 Why reuse needs an extension
Current common revision code instances.rs1430 documents preserve_order/JSONB key-order instability. Its valid_from hash uses nanoseconds but PostgreSQL persists microseconds. Current REST canonical_json iterates keys without explicit sorting, so its name is not proof of canonical bytes. PayRun's fixed typed digest remains useful legacy logic but lacks full NP1/FD1 wrapper binding. Do not reinterpret or rewrite old hash/receipt bytes. New commands use CCF1 and newly created enrolled draft chains use DRAFT_CCF1; add immutable integrity_protocol discriminator, bound into hashed data. Legacy rows are classified LEGACY_V0 and keep their old reader/digest algorithm; failed legacy recomputation is an integrity-uncertain condition requiring qualified repair, not automatic accusation of tampering or permission to reseal. No legacy draft-chain conversion in this slice.

CF1.2 Canonical restricted JSON
Use the existing serde_json parser/UTF8 and SHA256 dependency with an explicit ordered writer in ontology/application, shared by enrolled owner normalization. This is a closed typed canonical format, not a claim to implement every RFC8785 number case. Accept only object/array/string/boolean/null after strict typed decoding; NO JSON numeric values. Integer/Won/revision/timestamp values become canonical decimal strings, avoiding floating point and JSONB numeric spelling. Reject duplicate raw JSON keys BEFORE conversion to Value/JSONB, invalid UTF8/unpaired surrogates, decoded U+0000 (PostgreSQL text/JSONB cannot store NUL), undeclared fields, overlong/deep inputs and invalid discriminants. All map keys are registered ASCII names or lowercase UUID field IDs; serialize keys explicitly ascending ASCII byte order at every nesting level, never relying on Map insertion order or feature flags. Arrays retain schema-defined order; set arrays are duplicate-free and sorted by canonical element bytes after typed normalization. Lists with stable element IDs are still ordered unless declared set.
Canonical output is UTF8 without BOM/whitespace. Escape quote and backslash; use short escapes for backspace/formfeed/newline/carriage-return/tab, lowercase \u00xx for other admitted controls belowU+0020 (U+0000 is rejected before encoding); leave other valid Unicode scalars including U+2028/U+2029 unchanged. Literal text containing the six printable characters backslash-u-0-0-0-0 is valid text and distinct from a decoded NUL; escaping cannot smuggle NUL into storage. No Unicode NFC/NFKC normalization: two different textual notes stay different input. No trimming narrative unless its exact schema explicitly defines trim normalization; immutable note bytes and typed reason remain bound. UUID inputs must canonicalize through UUID parsing to lowercase hyphenated strings; no nil sentinel identities. Dates parse to real YYYY-MM-DD; instants normalize to signed decimal Unix microseconds. A wire timestamp with sub-microsecond remainder is rejected, not rounded into another event. Server observation clock is floored to microseconds before storage/hash. Positive integers reject leading plus/zeros and exponent/fraction forms on the canonical wire; typed legacy transport conversion must be explicit, not guessed. Booleans are true/false, not string tokens. Missing optional and explicit null differ; every required nullable envelope slot is present as null when absent.
Limits: request64KiB, normalized input64KiB, max128schema fields, nesting8, per-field/list bounds declared and capped256elements; checked before allocation-heavy parsing/normalization. Large payroll population is an immutable owner manifest ref. Exceeding bound refuses input, never truncates. These are proposed format bounds, not measured CPU/memory proof.

CF1.3 Exact fingerprints
Command bytes = UTF8("console.command.ccf1") || 0x00 || CCF1(normalized_command). Fingerprint SHA256, stored32bytes. Required envelope keys: protocol,org_id,command_id,actor_account_id,owner_key,owner_action,object_type_id,action_type_id,input_schema_ref,codec_version,target,body,expected,reason,attempt,gate_ref. target is exactly Existing{kind,object_id} or Create{kind,allocated_object_id,scope_ref}; refs carry Company and registered owner/type/revision, not untyped UUID. attempt is null only if current registration permits direct execution AND the server proves that Company command ID has no reserved/terminal attempt provenance under DA1.5, otherwise {attempt_id,draft_id,source_revision_id,editing_epoch,assignment_generation}; immutable original binding not current session/permission. Gate ref binds exact request+revision as declared by owner. Input schema ref and codec are immutable registered values. Relevant basis refs and evidence are in typed body/expected. Original transport names, current defaults, current policy epoch and ephemeral session token/CSRF are excluded; they cannot change the identity of already committed intent. Current authority is evaluated separately. Changing action/type/target/actor/Company/reason/expected/attempt/gate changes the fingerprint; reordering object keys does not. Original normalized command remains available for exact replay comparison under retention; minimal retained fingerprint may refuse old mismatched replay after payload disposal, without exposing it.
The active intent-slot key uses SHA256(UTF8("console.intent-slot.ccf1") || 0x00 || CCF1({org_id,custody,action_type_id,target_binding,intent_slot})); the start owner validates each component. It is an internal uniqueness aid, not readable context or a permission grant.
Save/start/restore/seal/cancel use the SAME envelope with common draft owner action and typed operation body. They bind original patch/context/expected revision, not a recomputed whole current draft. No-op ACK has the same immutable request binding. Schema-registry command schemas and product typed decoders must agree; envelope vectors are necessary but not proof of all source command bodies.
Revision bytes = UTF8("console.draft-revision.ccf1") || 0x00 || previous_hash raw32bytes || CCF1(revision_record). Genesis previous_hash=32zero bytes. Record includes integrity_protocol,org_id,instance_id,revision_id,version,object_type_id,input_schema_ref,attributes,valid_from_us,recorded_at_us,action_type_id,actor_account_id,reason; all integers decimal strings. valid_to is excluded because interval closure mutates it. Every included field and integrity_protocol is immutable under an updated append-only trigger; discriminator must not be toggled to bypass verification. Under locked head choose valid_from_us=max(server_clock_us,previous_valid_from_us+1); recorded_at_us remains actual normalized observation. Business effective date stays a typed attribute. Overflow or inconsistent head/open revision is failure. JSONB readback is canonically re-encoded and hashes identically for new rows regardless of key order. Existing ordinary business hash format and times remain unchanged.
Encoding vectors are literal synthetic reference data generated independently in Python for this document. They include transport-key permutation, newline/Korean text, absent/null, changed scope/actor/action/attempt and revision microsecond witness. They are NOT Rust/DB execution tests or proof that current code meets CF1. Later approved tests must compare literal encoded bytes and hashes in Rust and PostgreSQL roundtrip, including invalid duplicate-key/numeric/sub-microsecond inputs; Value equality alone is insufficient.
