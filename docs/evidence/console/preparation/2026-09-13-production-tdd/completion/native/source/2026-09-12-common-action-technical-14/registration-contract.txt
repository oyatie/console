CA1 — Registered types, actions and typed input

CA1.1 Reuse and source correction
The registry already stores immutable schema snapshots: ont_object_types.id identifies one Company/type/schema_version, child ont_action_types and ont_property_defs belong to that snapshot. Migration0165 revokes child UPDATE/DELETE and rejects changing an existing action definition; stage after publication creates another object-type snapshot. Reuse that owner, its catalog allowlist and publish commands. ont_object_type_key_revisions is a current key guard, NOT an immutable historical schema row. A receipt/attempt pins the actual immutable type/action row and input-schema revision, never just that guard's current number.
Action local stable_key is a SINGLE segment by0152 CHECK (create_run); logical owner action is dotted (payroll.create_run). Keep these separate and bind them explicitly in registration.csv. The route's action key alone cannot name an executable owner. No alteration of the local-key grammar or tenant-supplied dispatch callback. Existing six canonical ObjectKey and thirteen DispatchTarget roster remain actual production state; the named additions here are proposed, not an already expanded runtime.

CA1.2 Minimum registration extension
Add ont_action_runtime_bindings for immutable binding of exact Company/object type snapshot/action row to registered owner action, owner object, input-schema family, owner codec version, fingerprint protocol, custody requirement and supported result contract. Its fields cannot retarget after creation. The schema publisher and actual domain owner jointly validate the compiled registration; a tenant cannot declare arbitrary SQL, backing table, Rust symbol or owner action by text. Company epoch and type-key guard participate before publication. Live executable eligibility comes from current type/binding enrollment and owner compatibility, not the historical existence of that row. Old published snapshots remain readable when authorized; retired/incompatible versions cannot start or seal new effects. Existing sealed versions can execute only if explicitly still supported by the current owner/authority compatibility set; no implicit latest-schema conversion.
Add ont_action_input_schema_revisions because editor schema may evolve without changing the pinned business action codec. This is the ONE source of typed input structure, editor partial states, fields, constraints and normalization. Existing params_schema on enrolled rows contains its immutable schema-family binding, not a second handwritten ruleset; the enrolled preparation branch loads the exact revision. Legacy validate_params behavior remains compatibility-only and cannot admit this branch. Schema publication validates exact output compatibility with the compiled owner command. Schema changes can change form layout or add supported optional inputs; changing business meaning/codec needs a new action binding and a new intent, not in-place retargeting.
Each typed schema defines stable field UUIDs and technical ASCII names, scalar/ref/list/record/tagged-union structure, bounds, optional-vs-null behavior, coupled conflict group, source-provenance modes, required-on-submit and safe partial edit cells. Exact field identity is (input_schema_id,field_id); it is a registered Draft property identity for Cedar, never a label. Schema revision stores these definitions as closed typed JSON, checked by its owner; missing/duplicate IDs, foreign field-group references and unresolved validators block publication. No executable downloaded renderer or free-form validator name. Lossless upgrade mappings are registered versioned typed mappings owned by the same schema family; ambiguous transformations require explicit repair. Old definitions and required codec support survive through retained attempts/history.

CA1.3 Draft type and closure
Register one fixed instance-backed object type action_input_draft with owner capability INPUT_DRAFT_V1. Attributes have exactly schema_ref,cells,provenance,basis_refs. Cells are keyed by registered field UUID, containing Unset, Incomplete{bounded editor_text}, or Value{schema-typed value}; Clear in a patch normalizes to Unset or explicitly allowed business null, never an omitted whole-object replacement. Lists have stable element UUIDs; ordered lists preserve order, set-valued lists reject duplicate identities and sort canonical identity for normalization. Reference discovery/edit/save and target validity are current owner checks; Incomplete search text is never a link. Date/Won/revision values are typed, not arbitrary JSON or LLM interpretation.
The published draft type explicitly installs guarded draft actions. Migration0165's automatic generic create fallback must never publish an unguarded create on this type. All generic create/stage/lifecycle/writeback/import/link/traversal/history/search/aggregate/receipt endpoints enforce its owner admission or refuse it. Generic instance helper functions remain common implementation machinery, but callers cannot use them as an alternate public write path. Ordinary types retain existing validation; admitting DraftCell does not relax them.
Common draft controls and normalized submission attempts are addressable through authorized object projections, without pretending either is a canonical projected PayRun. Draft payload revisions stay in the existing common instance store. A business result remains domain-owned and linked to its proposal; no generic rename of a proposal into PayRun, and no generic writer of wage or tax facts.

CA1.4 Owner additions and boundary
registration.csv maps all10NP1 commands to exact local keys, proposed/existing projected owner kinds and result contracts. ContractWage and TaxEvidence require explicit canonical roster + ownership table inventory + receipt CHECK changes; existing wage SQL stays with payroll adapter, no second writer. Tax evidence physical tables and source nested types remain W04b-03: their registration is unavailable until that owner's actual schema, codecs and proofs exist. PayRun commands reuse PgPayRunPort, with the needed typed query variants. Common draft commands are ontology.action receipts with a typed common target extension, not false PayRun receipts.
Existing CanonicalPort::command lacks full NP1 envelope and canonical_port_handler drops outer reason. Extend the responsible canonical application/port request type for enrolled commands to carry exact registered action, typed target/body/expected refs, reason and optional exact attempt/gate bindings. Direct domain REST and common Action normalize to the SAME owner request. Duplicate outer/inner command, reason or gate fields must match; mismatch is422 before effects. Do not silently use a transport-specific reason or UUID. Source/evidence nested codecs remain explicitly unavailable until W04b-03; a generic VersionRef string placeholder is not an executable DTO.
