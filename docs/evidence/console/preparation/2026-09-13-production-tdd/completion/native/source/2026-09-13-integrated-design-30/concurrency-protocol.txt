CP28 — Comparable concurrency experiments
Status: protocol proposal; no architecture selected by this document and no load experiment executed. This refines research2026-09-13-enterprise-concurrency at frozen6c8cbd4; notably X11 exactly-one is conditional as below. Employee counts are dataset dimensions, not concurrent writer counts.

1. Comparison unit
A candidate is a complete assembly: physical storage and versioning, read/write/predicate conflict control, scheduling/ordering, replication/durability, projection/editor adapter and external effects. Labels such as MVCC, queue, CRDT or Raft describe different axes and do not constitute competing complete products. Include current baseline, single-version OCC with complete predicate validation, serializable multiversion transactions, scoped strict locking, deterministic ordering, partition-owned state machines and selected editor algorithms only where an implemented adapter has equivalent semantics. No custom consensus required by this protocol. Existing architecture earns no correctness or performance exemption.
Freeze identical initial logical state, original intent arrival trace, payload/dependency graph, key skew, source/policy state, allowed outcomes and durability/fault boundary. Different physical layout is legitimate; report index/history/replica amplification. Equal total resources include generators separately, database, coordination replicas, queue, cache, workers, journal and formula execution. Persist exact binary/source/config/schema hashes, hardware, network RTT/loss and cache state. A local render, volatile echo or queued admission is not a durable edit or business effect; each ranks only within its own boundary.

2. Logical histories
Each original intent has intent_id; each immutable command has command_id and canonical input digest; retries carry attempt_id and retain command_id. Explicitly revalidated proposals get a new command_id linked to original intent; only a new user objective creates a new intent. Record synthetic tenant/Company/actor/policy context, exact targets and expected semantic revisions, scheduled arrival, invocation/response intervals, admission evidence, allowed outcome code and authoritative receipt. Every command's reads, negative predicates, membership observations and dependency checks needed by its oracle are recorded, as are policy/gate/hold/retirement transitions and faults. Never place real wages, credentials or tenant identifiers into public benchmark logs.
Use causal links, invocation/response intervals and independent durable owner evidence for cross-machine ordering; wall clocks alone cannot establish it. A lock timestamp cannot be the sole evidence validating that lock implementation. Check authoritative intermediate transitions as well as final state. Catch-up is not permission to repair an invalid historical commit and call the run correct.

3. Common oracles
Contradictory scalar writes against the same expected semantic revision cannot both succeed; rejected proposals survive in authorized conflict UX. Independent fields preserve both updates only when no shared semantic group or predicate couples them. Coupled predicate example x=y=40, x+y<=100, two commands each add15 after reading the sum: at most one succeeds at those observations. Per-row CAS alone does not meet this contract.
A population-dependent action binds a complete membership set at one permitted ordering point, with new eligible members either before or after it. Changed inputs can require re-resolution; mixed membership and hidden exclusions are invalid. A pin acquired while a unit is admitted prevents retirement until authorized release; begin_retirement closes new admission before releasing descendants. Without intervening release, pin acquisition and retirement cannot both succeed. This semantic requirement does not prescribe a lock.
A new effect requires valid authority/source/gate at its authoritative commit boundary. A command overlapping completed revocation may order before it; a command invoked afterwards cannot use the revoked grant. Deadline expiry is checked at the specified final boundary. A successful historical receipt can be replayed under current disclosure without new effect; it is not renewed authority. One-use gate consumption, sealed-input binding, owner effect and receipt have an atomic outcome.
Every command has effects<=1. Eventual exactly-one applies only to a valid durably admitted command that the fixture requires to complete after service recovery; zero is legitimate for definitive no-effect rejection/cancellation. Timeout is an observation, not no-effect evidence. Unknown histories remain INCONCLUSIVE until resolved or explicitly isolated with protections retained; the oracle cannot discard unknowns or invent a convenient completion.

4. Actual-code fixtures and semantic decisions
K01 period freeze: gated September staging pauses after final no-freeze read. Concurrent September freeze must order consistently through publication; successful committed replay remains available subject to current disclosure. October freeze is a disjoint control. Existing key is Company+domain, not month; canonical staging has an explicitly ungated path. Enrolled new protocol writers must converge or be denied; this census alone does not prove all paths enrolled.
K02 attendance close: current key orders close operations only, not new leave/exception writes. Selected business contract for the candidate: a close is an immutable snapshot of complete month/scope observations at its recorded ordering point. Later backdated facts append a stale-basis marker and route correction/reclose; they do not silently alter the old basis or suppress legitimate leave. New payroll publication validates that the selected basis is still current for its sources. Closing UI displays unresolved blockers and correction ownership. This chosen contract needs independent integrated review; it is not a finding that current code already enforces it.
K03 substitution versus leave: assignment published after approved overlapping leave must revalidate and refuse/replan. Leave recorded after assignment invalidates affected assignment readiness and creates one idempotent reassignment work item atomically with the business decision; no automatic leave denial. Both owners use the same actual half-open time-window overlap function, not date-only trigger versus AM/PM Rust disagreement. Pending reassignment remains visible, cannot count as coverage, and retains an accountable owner. Disjoint AM/PM and different-worker controls must both be exercised. These are proposed semantics, not legal conclusions.
K04 branch coverage: count full eligible roster and overlapping approved absence at the same defined point. Competing roster/absence changes must be validated as predicates, not merely versions of the requester's rows. Negotiation is an action result with evidence and follow-up; no invented statutory denial rule.

5. Accounting and fairness
For a fixed offered cohort O, count each original eligible intent once. A is durably admitted at the declared boundary; S is successful with boundary evidence. Outcomes success, definitive rejection/no-effect, cancellation and unresolved partition O. Invalid/adversarial traffic is a separately reported cohort. Retry/timeout/unknown-response observations may overlap eventual success. Useful throughput S/cohort interval includes every original offered intent in accompanying outcome counts; retries cannot inflate S. Deadline success ratio is S within D / O, plus admitted-only diagnostic ratio. Capacity rejection never becomes an expected semantic conflict to improve a score.
Measure latency from intended arrival and actual send; record rejected latency and unresolved age separately. Generator saturation invalidates capacity comparison. High-contention fixtures declare expected semantic conflicts in advance. Fairness measures independent victim traffic while the hot key is active; separately measured best-case throughput is insufficient.

6. Loads and limits
Use frozen research hypotheses: 2k/50k/1m people; normal2% active at0.2ops/s gives8/200/4000ops/s; burst10% at2ops/s gives400/10000/200000ops/s. Sweep1..1000 editors and hot-key fraction independently. Include one Company, six Companies with90% skew, many Companies and multiple independent customer Groups. A million employees does not require a million simultaneous edits. Formula graphs100/10k/1m nodes and bulk source inputs stress dependency work separately.
Every run MUST freeze maximum queue count/bytes/age, retries per command, unresolved/rejection/error budget, memory/storage/connection budget, protected-neighbor degradation, recovery deadline and backlog drift tolerance. Absent values mean NOT_ASSESSABLE, never PASS. The run template intentionally has unselected implementation/hardware/limits; it is not executable readiness. Proposed interactive latency targets remain local p95<=50ms, durable draft p95<=250ms/p99<=1s, small commit p95<=1s/p99<=3s for a specified network fixture; bulk completion uses input-size budgets. These are candidate acceptance requirements, not existing SLAs.
Stages: oracle conformance with forced schedules first; independent/disjoint and hot-key ramp second; failure and recovery at admitted loads third. At least3 repeats per fixed environment/rate; declared60min steady plus10min burst/hot phase;1s observations and5min windows. Each window must meet all frozen bounds. Record sample sufficiency (>=10000 interactive attempts for tail analysis or insufficient sample), no silently shortened run. Highest tested rate passing every required repeat and lowest tested failure form a capacity bracket with cause, variance and inconclusive gaps. No interpolation into an exact maximum. Finite bounded backlog observation is not a mathematical stability proof.

7. Recovery and stopping
Inject process death, response loss before/after commit, storage partition, old-owner resumption, clock skew, policy revocation, lifecycle hold, journal outage and duplicate delivery at named boundaries. Recovery begins at declared fault/fence event, finishes only when owner is uniquely authoritative, acknowledged work meets declared durability, unknown commands are reconciled or isolated, backlog below limit and declared consecutive windows meet targets while offered load continues. Zero-arrival drain is reported separately.
Correctness violation stops that candidate immediately and retains the counterexample. Load limit breach marks failing capacity, not permission to weaken the invariant. Stop admissions before unbounded memory or retry amplification; preserve acknowledged input and truthful queue/conflict/unknown state. A provider or authority prerequisite failure excludes the affected capability from acceptance, never converts refusal-only behavior into positive functional coverage.

8. Evidence classes
Static packet validation checks artifacts and references only. Analytical examples or schedule enumeration reject toy algorithms only. SQL integration, actual Rust tests, Verus actual-exec proofs, load experiments and deployed recovery drills each require their own execution records and exact versions. None has run as part of writing this protocol. After approved design, executable tests must bind fixtures here; architecture selection must record complete assembly, measured tradeoffs and migration cost, not a mechanism popularity claim.
