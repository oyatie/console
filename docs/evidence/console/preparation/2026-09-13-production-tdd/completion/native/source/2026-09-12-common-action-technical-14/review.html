설계 증거 · W04b-02 · 제품 구현 아님

작성한 입력부터 실행 결과까지, 하나의 연결된 기록

기존 객체 버전 저장을 재사용하고, 저장·제출·실행·인계를 실제 소유자에 연결하는 기술 제안입니다. 범위별 최종 상태는 후속 독립 검토 기록을 확인하세요.

사용자 흐름

  • 작성 중 저장은 초안만 바꿉니다. 급여·계약·업무 완료는 명시적인 실행에서 바뀝니다.
  • 두 탭의 수정은 조용히 덮어쓰지 않습니다. 독립적인 변경만 합치고 충돌은 필요한 정보와 함께 보여줍니다.
  • 제출할 내용은 고정됩니다. 실행 응답을 잃어도 같은 요청의 결과를 확인하고 중복 처리하지 않습니다.
  • 인계는 작업 단위로 진행하며, 이전 담당자의 미실행 요청은 확인·취소한 뒤 새 담당자가 이어갑니다.
  • 과거 입력 복원은 새 버전을 만듭니다. 과거 권한이나 승인까지 되살리지 않습니다.

기술 결정

별도 Git·이벤트 저장소를 만들지 않고 공통 버전 저장을 확장합니다. 편집 이력과 불변 제출 스냅샷의 역할을 구분하고, 감사 기록에는 민감 입력 전체를 복사하지 않습니다. JSON 키 순서·시간 정밀도 문제는 새 버전의 인코딩 규칙으로 다룹니다. 기존 해시는 보존합니다.

  • 객체·액션·입력 스키마 등록
  • 저장·봉인·실행·인계·복구
  • 정규화·명령 지문·버전 무결성
  • 4개 제안 제어 테이블과 기존 구조 확장
  • 10개 급여 명령의 소유자 매핑
  • 12개 참여 계약과12개 입력·동작 경계
  • 합성 인코딩 증거10개
  • 비실행 검증 후보34개
  • 전환·검증·남은 구현 준비

소스별 상세 입력 형식, 업무·전사 엔진, 실제 DDL·DB 권한·보관/복구·부하 검증은 남아 있습니다. 이번 문서는 동작하는 제품이나 최종 통합 설계 승인이 아닙니다.
