## Ordinary publisher contract refinement

Responsible existing package: `backend/crates/platform/auth`, sibling ordinary `terms_publication` module; deployment/release startup wiring in existing `backend/app`. This is the normal BW31 operator-only release command. It has no public HTTP route or tenant caller-selected config/path. There is no special acceptance/bootstrap publisher namespace.

`load_deployment_custody(config_path:&Path, Environment)->DeploymentCustody` loads a deployment-owned local immutable configuration, permitted operator public keys, separately qualified content authority public keys, registered kinds, fixed local object/approval paths and dedicated publisher DB LOGIN. The caller is the privileged OS/deployment release command, not an app request. `DeploymentCustody` has private fields and no public constructor/Deserialize.

`begin_operator_authentication(&DeploymentCustody, operator_key:&str)->OperatorChallenge` issues fresh bounded one-shot challenge bytes. `OperatorChallenge::signing_bytes()` exposes the exact domain-separated deployment/operator/challenge/expiry bytes to the signer; private challenge fields cannot be constructed by tests. `finish_operator_authentication(DeploymentCustody, OperatorChallenge, proof:&[u8])->AuthenticatedOperator` verifies Ed25519 against the configured key, challenge identity/time/replay and custody. `AuthenticatedOperator` is opaque and publisher-scoped; it is not an Account session or general deployment administrator.

`publish_terms(&AuthenticatedOperator, OperatorApprovalRef)->PublicationReceipt`. `OperatorApprovalRef` is exact BW31 `{kind:OPERATOR_RELEASE_APPROVAL,approval_sha256:lowercase_sha256}`; Rust enum variant `ApprovalKind::OperatorReleaseApproval`. Resolve only the configured immutable `approvals/{sha256}` object and detached signature, never a caller path. Verify exact closed `TermsPublicationApproval` bytes, signed independently qualified content reference bytes, fixed approved manifest and each registered local content object. Checks include UTF-8, exact digest, all capacities, distinct required registered kinds, signed expected/next revision, TEST_ONLY exclusion in production and local-file no-symlink/escape rules. Test Ed25519 signatures use OpenSSL's actual one-shot implementation, with two independently generated keys. Signature envelope/path/qualification encoding is a proposed ordinary deployment-custody refinement, not an existing implementation claim or legal authority.

`PublicationReceipt` fields used: `id:Uuid`, `previous_revision:Option<i64>`, `revision:i64`, `manifest_sha256:String`. Return only after committed ordinary publisher transaction and preserve exact approval bytes. `PublicationError` variants used: `RevisionConflict{current_revision:i64}`, `UntrustedCustody`, `InvalidArtifact`, database failure. No response-loss replay guarantee is invented for publication.

SQL registration: `public.account_publish_terms(jsonb)` is the proposed sole SECURITY DEFINER mutation helper, owned by a non-login migration owner, fixed qualified `search_path`, PUBLIC revoked, EXECUTE solely the dedicated `console_terms_publisher` LOGIN. JSON input remains an untrusted approval reference: the OS custody owner must produce transaction-bound verified input without exposing a runtime-callable verified-approval constructor. A generic JSON helper cannot independently confer OS custody authority; implementation must bind its exact internal transaction proof/capability to the authenticated publisher and close direct publisher-role forgery if that role is exposed outside the one-shot release process. Tests exercise real runtime LOGIN calls with valid approval bytes and the normal authorized positive path.

`CustodyFixture::new(label,database)` writes a private temporary bundle with mode0400 files and a dedicated `CONSOLE_TERMS_PUBLISHER_DATABASE_URL` targeting only the supplied marked `_sqlx_test_` database. Fixture setup must bind this URL to the same isolated PostgreSQL instance as the existing marked administrator; it never grants the role or manufactures catalog rows. `approve` signs exact BW31 bytes; `authenticate` invokes the ordinary verifier. The B5 frozen copy pins the preceding producer hash; integration must explicitly update that dependency to this packet's reviewed exact hash if it differs.

## Account, topology, policy and projection interfaces

Use B5 ordinary first-operator cold-start, provider-registration, supervised-root and Company-enrollment contracts, including exact signed provider revision and explicit `&JwtVerifier`. Publication commits genesis before root proof/Account enrollment. The real deployment startup auth LOGIN and identity command LOGIN are required; the helper verifies actual `session_user/current_user`. No caller-set admin flag or fabricated Account/Company row is introduced.

Account `PasskeyService` and `JwtVerifier` are the real existing cryptographic types. Every Account fixture signs the actual returned WebAuthn challenge; the actual finish and `verify_account_session` validate the minted ACCOUNT_V1 plus stored refresh family. Test config must pass the same immutable issuer/verifier/terms registry into the actual owner/service instance; no process-global mutable test override is admitted. `AppState::serving_admission_binding()` returns the actual already-admitted process binding, not a DB-row-to-authority constructor.

Normal Account-aware provisioning siblings used: `read_account_group_control(pool,operator,group_id)`, `update_account_group(pool,operator,GroupUpdate{command_id,group_id,expected,name})`; corresponding Company `read_account_company_control` and `update_account_company(CompanyUpdate{command_id,org_id,expected,name})`. These extend existing `PlatformProvisioner::{create_group,update_group,onboard_tenant}` at that owner. They require current operator authority and guard control, update actual labels/topology epochs atomically and return current recorded control; they cannot accept arbitrary table/field names.

Identity `read_company_policy_schema` and `read_group_policy_schema` are ordinary registered-current-schema readers. Their `action(key)` and `projection(key)` lookups must resolve actual current ActionRef and GovernedRevision under the enclosing Company/Group; lookup keys do not confer permission. They are not claimed to exist in design30's current action register. Final registry identity approval is a production schema/registration prerequisite; a test manifest cannot silently install the corresponding permit. `PolicyScope::Company` and `PolicyScope::GroupControl` are untrusted closed grant choices, never verified contexts.

Use B5 `read_company_policy_control` and `apply_company_grant_plan`. `CompanyGrantReceipt{org_id,grant_id,...}` maps `grant_id` to actual design30 `policy_assignment_revisions.assignment_id`. Add ordinary `revoke_company_grant(RevokeCompanyGrant{command_id,org_id,grant_id,expected,reason})` and `restore_company_grant(RestoreCompanyGrant{...})`; restore appends a new current grant/revision from historical input, preserving old revocation evidence, and never erases a revocation. ## Migration and admission interfaces

Responsible existing module owners: existing `backend/app/src/lib.rs::run_migrations` and its migration/admission lifecycle; proposed ordinary `console_app::{account_migration,serving_admission}` modules. Actual schemas are prerequisites. The fixtures never create these product tables or implement mapping/backfill themselves.

Migration uses installed immutable `load_installed_manifest(config)`; `capture_source_snapshot(config,manifest)` binds actual source IDs/versions/cursor and an immutable versioned source manifest. The row/version probe in this packet is specifically old `users(id,xmin)` input; enrollment must define the exact old identity source family and dependency-version closure. `BatchRequest{manifest_digest,source_cursor,source_version,batch_id,limits:{max_rows:500,max_bytes:4194304,statement_timeout_ms:2000}}`; `migrate_batch(config,&request)->MappingReceipt` commits ordinary mapping or quarantine and durable receipt. Receipt fields used: `source_keys:Vec<(Uuid,String)>`, `source_bytes`, `statement_timeout_ms`, `next_cursor`; derives exact equality for replay. New absent relations used by independent readback are `account_migration_mappings`, `account_migration_quarantine`, `account_migration_batch_receipts`, keyed by source identity/version and manifest. Quarantine keeps exact source bytes/digest and registered reason `UNRESOLVED_IDENTITY_PROVENANCE`. These names and physical columns are explicit migration refinements requiring schema approval, not implemented catalog. Exact duplicates are rejected before conversion to sets.

`pause_legacy_admission(config,manifest)->DrainRequest`, `drain_legacy_work(config,&request)->DrainedLegacyWork`, `commit_account_cutover(config,&drained)->PermanentFenceReceipt`; returned controls are opaque and require actual paused admission, drain/UNKNOWN reconciliation and generation witnesses. Existing legacy refresh/OTP owner calls test the installed fence after real cutover.

Serving startup uses `load_installed_release(config)`, ordinary closed `ReleaseDescriptor::parse(bytes)`, `admit_process(config,descriptor)->AdmittedProcess`, `pause_and_drain_effects(config)->DrainedEffects`, `advance_recovery_generation(config,&drained)->RecoveryGenerationReceipt`, `revalidate_serving_binding(config,&binding)`. Types returned by admission are opaque; parsing a descriptor does not create service authority. These are not missing test helpers; their actual production module implementations are required before compiling/running.
