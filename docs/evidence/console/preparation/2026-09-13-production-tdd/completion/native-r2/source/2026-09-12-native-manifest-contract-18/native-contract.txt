NM18.2 Exact source slots and bounded input
native-types.schema.json is a closed JSON Schema shape specification. Semantic rules, raw duplicate-key refusal and i64 bounds are separately mandatory in scalar-and-encoding.txt and source-slot-cardinality.json; JSON Schema syntax alone is not authentication, source qualification or current validity. Every object declares all fields and additionalProperties=false. There is no arbitrary payload/TypedRef at the native slot boundary. Referenced source-owner contents remain immutable owner records: do not flatten all attendance events, artifact versions and professional trust chains into every employee slot. Source owners must retain and revalidate that bounded dependency closure; their remaining F01/F02 contracts are listed explicitly in readiness.json.
Header stores exact ProfileRef/RuleBundleRef and ScopeBasisRef once. Select profile/scope as registered common object instance revisions; profile_id/scope_id mean instance_id and revision means version, with Company/type/compiled owner registration verified. These are object identities, never arbitrary strings naming tenant-created legal algorithms. Do not reinterpret earlier frozen bytes; this native18-v1 codec binds the mapping. No source object or compiled statutory rule is implemented/enrolled here.
A source slot is (kind, selection, ordinal). SELECTED singleton kinds have ordinal0; selected Employment segments have ordered ordinal1..128. CANDIDATE references belong only to BLOCKED units and have ordinal1..32 per kind, sorted by canonical reference bytes. Selected and candidate lists never silently cross roles. RESOLVED requires one binding, contiguous segments of one Employment covering the whole header earning interval, one wage, one attendance coverage, one eligibility assessment and one tax evidence. BLOCKED retains available exact refs and nonempty typed blockers but forbids all normalized monetary/hour/tax-edition fields. Candidate ambiguity cannot be hidden by selecting first/latest; no duplicate full reference or gaps in declared ordinal sequences.
Ordinary input lists max256 refs and32 blockers per unit; normalized leaf max64KiB and depth8. If a bounded resolver cannot establish completeness, persist a BLOCKED slot with SOURCE_BOUND_EXCEEDED, the relevant family witness and only complete independently known refs; omit the over-limit candidate family as a whole, never label a truncated list complete. That is explicitly unresolved source work, not a successful empty result. If authoritative population itself cannot be completely enumerated, fail preparation without installing a new input head; never drop workers. Pilot input bound2000 required people per Company is a declared NP1 envelope (total pilot2000), not a permission quota or generic object-engine cap. Larger use requires a reviewed measured envelope. Counts and hidden identities never become public diagnostics automatically.
NM18.3 Header, stable lines and batch identity
Native run creation is header-only STAGED, run_revision1, current_input/calculation/close null. Explicit pay_date is stored, not silently period_end as current legacy calculate does. Prepare materializes one stable NP1 line per exact Company/run/employee with source key native:<lowercase employee UUID>, zero import refs and immutable identity. Legacy lines retain their nullable employee/source-key behavior. A removed employee's line remains historical; native current reads join the current input/batch membership, never all run lines. Source note and employee display fields are not identity or calculation input. Every native successful calculation binds Company/run/line/employee/input/batch/RESOLVED status and exact source basis. None of these correlations is implied by a globally unique UUID alone.
Input revision is positive i64, allocated as max committed input revision+1 under the run fence. Calculation revision is explicitly1..2147483647 to match existing INTEGER/version and i32 readers. Allocate max committed BATCH revision+1 under that fence; clearing the active pointer cannot reset history. On exhaustion refuse with REVISION_EXHAUSTED, preserve history and require a reviewed compatibility migration. No widening or wrapping in this candidate.
Each batch references its exact input header and close basis. Every input employee has exactly one immutable payroll_calculation_units outcome for that batch. SUCCESS points to exactly one existing payroll_line_calculations row; BLOCKED has nonempty typed blockers and no result reference. No successes may exist outside the outcome set and no outcomes outside input membership. Header counts derive from that set and must equal it at transaction commit, including zero-success batches. An empty required population never creates a batch. The stable line projection may update readiness but cannot serve as the historical outcome source.
