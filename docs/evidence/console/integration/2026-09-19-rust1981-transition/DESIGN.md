# Required Rust 1.98.1 compiler transition

The user release contract explicitly retains Rust 1.98.1. The current canonical root pin is nightly-2026-09-10. Prior Account integration deliberately preserved that inherited pin and recorded stable-toolchain qualification as separate required work. This proposal executes that requirement, with no dependency updates or historical evidence changes.

Root is the sole writer. The only source changes are rust-toolchain.toml channel and the generated toolchains/rust/lock.bzl. Root generates the lock using the existing scripts/lock-rust-toolchain.mjs parser/buildLock/renderBzl and the official version-specific channel-rust-1.98.1.toml snapshot. Preserve components rustfmt/clippy, wasm target, three native host triples and all artifact digest/URL/strip-prefix rules. No manual generated-field changes, floating tag, nightly-only fallback, or other pin authority.

The provided probe.mjs is an executable configuration acceptance probe for this exact release contract, using the canonical parser. It must fail with RELEASE_RUST_PIN on the clean committed test candidate before fanout admission and pass after the two-file transition. Existing toolchain-pin and lock-generator adversarial suites remain unchanged. They verify alignment, missing packages, exact versions and compiler artifact identity. No test deletion, relaxation, or migration of expected historical fixtures.

Compatibility before editing: root ran a separate-target Cargo 1.98.1 check for console-app --all-targets, with SQLX_OFFLINE=true and --locked; it passed in 57.77 seconds. Leptos hydrate/islands release WASM compilation under the same explicit compiler is running separately. These are build checks, zero runtime tests, and do not qualify browser behavior or the whole release. Do not edit the pin unless the WASM check also passes.

After admission: change the root channel to 1.98.1 and regenerate the lock through its existing owner. Run the same exact probe, unchanged generator/pin suites and gate; regenerate --check against the same official snapshot or independently verify live version-specific manifest equality. Run default (no explicit +version override) rustc -Vv and Cargo app all-target check to prove normal root invocation selects the new compiler. Exercise an unchanged real Account designation owner test using the dedicated disposable database harness under this pin. Verify SSR/WASM build and compiler provenance; committed bundle regeneration and browser interoperability remain their own qualified artifact step when the artifact changes.

Rollback is a reviewed revert of the two configuration files, which restores the inherited compiler and byte-bound Buck lock together. Existing Cargo/Buck caches key on compiler bytes; preserve previous target directories and receipts. Do not reuse old compiler run evidence as new proof. No database, command bytes, SQL, lockfile dependencies, TLS configuration, global rustup default or installed toolchain is changed.

Pre-mortem: incompatible crates or hydration, missing upstream target package, stale compiler cache, generated-lock drift or wrong default resolution. Detection is the pinned app/WASM build, existing adversarial gate and actual owner execution. Stop on missing prerequisites, hash mismatch, any unexpected source/generated diff, incompatible behavior or a need to weaken tests. No production exposure, source release, legal or complete-release acceptance follows.

Remaining explicit required work: backend/Dockerfile currently references nonexistent backend/rust-toolchain.toml and pins its own builder image; a source-bound container-build repair and deployment-equivalent Linux build/runtime qualification remain necessary. This narrow canonical-pin transition does not claim to fix the Dockerfile, qualify all workspace packages or clear the macOS nextest descriptor-inheritance defect.
