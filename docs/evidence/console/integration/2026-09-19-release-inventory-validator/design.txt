## Bounded first lane

Allowed implementation paths: scripts/console/validate-console-truth-ledger.mjs and its existing .test.mjs. Reuse object, nonempty, SHA/SHA256, repositoryPath, resolveSource, and existing JSON/immutable-candidate mechanisms. Add one private release-inventory validation helper called unconditionally from validateConsoleTruthLedger before validatedRegistries.set. All production callers thereby use it without a second call-site contract.

This lane validates current version1 structure and prevents self-asserted advancement. It does not invent a release-state promotion protocol. Until a separately reviewed state-specific verifier is implemented, reject any true implemented/integration_accepted/production_qualified/released value, including when arbitrary plausible receipts are supplied. That is an explicit unbound-promotion error, not a permanent claim implementation is absent. Planned work may retain descriptive evidence and blockers without those descriptions authorizing advancement. Production exposure/direct payments remain separate authority.

The existing verifyImmutableReviewReceipt cannot simply be attached to a new leaf: it binds old capability outcome IDs, reviewer ownership, canonical path, exact candidate, registry/jurisdiction digests, immutable commit bytes and trusted signing identity. It does not establish stage-specific deployment artifacts, executed counts, UX/performance/recovery outcomes or the complete release. Later state promotion must reuse that authenticated substrate with an independently reviewed mapping of every required stage outcome; do not accept strings/hashes merely shaped like receipts, add a caller-controlled boolean verifier, or alter historical receipt bytes/digest rules. promotionAuthorityDigests already covers release_inventory: preserve that behavior and historical receipts unchanged.

## Structural contract

1. Require own release_inventory object, version1, the three current authority paths, fixed target2026-09-19 and current state-policy order. Require nonempty families/leaves, scope/population fields, exclusions, cross-product outcomes and explicit blockers. Population remains Group1/Companies6/people2000/KR under the present user contract. Required families and exclusions are disjoint unique IDs; do not turn excluded AIP/direct execution into completed leaves.
2. Require unique leaf IDs within known declared families, required=true for this required release inventory, integer milestone0–10, nonempty owner/journey, object acceptance/evidence, and arrays of unique existing dependency IDs. Reject self-edges and cycles. Acceptance remains status=not_bound with null command/fixtures/boundary for current unbound version1 entries and a nonempty outcome. A subsequent contract-binding extension must explicitly define bound fixture/command types; arbitrary status labels cannot bypass this gate. Require declared blockers for unbound leaves. Do not hardcode154 as proof of completeness.
3. Require exactly the five state keys as own boolean properties in declared order semantics; planned must be true, later states cannot skip earlier states. Reject every later true state until its verifier exists. Reject missing/extra keys and string booleans. Descriptive evidence never overrides the states.
4. Require reference_freeze, current partial_snapshot status and incomplete coverage/blocker records. Unknown/complete status cannot claim a freeze without a separately bound coverage verifier. Source records require unique IDs, safe repository-relative artifact paths, positive integer byte sizes, lowercase raw/compressed SHA256, public URL metadata, valid recorded retrieval timestamp and limitations. Preserve both existing metadata variants: timestamp_basis/retrieved_file_mtime_utc and direct retrieved_utc/status/effective_url. Do not rewrite provenance to normalize the variants. Use supplied resolveSource to reject non-regular/missing candidate artifacts in authenticated CLI/planner use; default unit-test resolvers establish structure only.
5. Require source_bindings object. Every present leaf key must resolve; every binding must name a known source and match its path/raw digest, carry a nonempty quote and existing matching/scope metadata. Preserve both existing raw-digest field names (artifact_uncompressed_sha256 and sha256) while rejecting contradictory duplicates. Missing bindings for planned user-required leaves remain explicitly incomplete; require the binding section itself, but do not falsely require all154 leaves to have public quotes. Apply the same source-identity checks to runtime and models/admin qualifications and support-cell citations.
6. Require connectors/runtimes/sdks support matrices with status=incomplete, nonempty required_dimensions and entries of the observed row shapes. Check connector reference-path uniqueness and catalog_source resolution; runtime name uniqueness and source resolution; SDK language uniqueness and source resolution. Validate optional current models_administration dimension/values/source_binding rows too. Console acceptance remains the current explicit not-established statuses; command null does not imply support. Source-supported/unsupported/beta labels are vendor facts and must not be treated as Console qualification. Preserve all existing cells and qualifiers.
7. Preserve existing return verdict, adding release_leaf_count/release_source_count as structural counts only if useful. Mint the existing validated-registry tag only after both historical and release structural checks pass. Never dispatch a leaf because this structural function passed.

## Boundaries deliberately not claimed

This first lane does not hash/decompress HTML, prove quote entailment, prove the inventory is exhaustive, prevent every coordinated deletion that leaves a smaller internally consistent graph, or independently validate release evidence. resolveSource confirms tracked regular blobs in the candidate, not raw/compressed byte identity. Those limitations must remain visible, not be described as source-custody or completion proof. A later bounded source-custody check can use the existing immutable Git source resolver and bounded gzip decoding; never execute candidate-authored tools in pull_request_target.

Preventing removal of a required orphan leaf needs a separate trusted baseline comparison, not a154-count constant or second handwritten ID ledger. Reuse the signed candidate inventory already available in createConsoleCandidateSourceResolver and compare its required IDs against an authority-tip update, with explicit reviewed supersession mapping if ever allowed. A current-candidate-only structural pass cannot prove preservation across revisions. Do not claim it can.

## Failure, recovery and stop conditions

Pre-mortem: hardcoded counts mask omitted capabilities; loose states manufacture release progress; default resolvers appear to certify custody; historical fixture/receipt rewriting hides incompatibility; a fake test helper passes while actual CLI/planner bypasses validation.
Detection: actual exported-boundary mutation matrix, authenticated source controls, unchanged historical tests and exact counts. Blast radius: shared ledger validation and planning admission only. Rollback: revert bounded validator change; retain RED/evidence records and source history. Stop on need to weaken historical tests, reinterpret signed bytes, execute candidate code under elevated authority, require unproven accepted states, or confuse structural validity with implementation/exposure.

Remaining required work: independently reviewed promotion verification; immutable snapshot byte/quote checks; signed baseline preservation and complete source/support coverage; every product implementation/qualification requirement. This bounded safety correction does not complete milestone0 or the release.
